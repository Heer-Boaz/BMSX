## Original observation gap — closed in the public text

The earlier text correctly distinguished diagnostic output/history/drawing but ended the program in HALT and showed a monitor figure without the operation connecting those states. The revised public companion closes that concrete newcomer gap:

- The chapter now points to the companion's “ordinary-run procedure for observing diagnostic output and entering the monitor” (`system.md:263–265`).
- The companion supplies the exact ordinary-ROM command (`README.md:64–66`), expressly distinguishing it from the derived integration image (`68`).
- It identifies the terminal output, the real supervisor-request line asserted at presentation frame 82 and released at 84, the monitor capture at 90, and its generated path (`68–79`). The procedure does not invent a guest entry callable or substitute a keyboard key for the request wire.

The diagnostic/figure story is now coherent and reproducible **as a public procedure**: the terminal receives three diagnostic lines, while a later monitor draws only the two retained BIOS-history lines. The raw `Sé😀?` line is not in that history. The text explicitly warns that the earlier cartridge screen need not contain either BIOS print line because `print` does not itself draw (`README.md:75–79`; `system.md:253–255`, `475`, `478–481`). I did not execute this command or inspect the resulting image; those are separate evidence reviews.

## Accepted public contracts

| Reader task | Public evidence / conclusion |
|---|---|
| Locate and access all SYSTEM words | The stated 13 four-byte ports are expressly noncontiguous (`system.md:14–17`): CONTROL/STATUS (`19–22`), six fault words (`135–142`), three timing words (`219–230`), two diagnostic words (`242–245`). Their addresses, access, reset/state and readback meanings are given. |
| Distinguish CPU privilege from device context | Current CPU mode, not cartridge/library origin, gates supervisor commands (`28`, `60`); a cartridge interrupt routine executes after current user mode clears (`60`, `373`). STATUS is expressly not privilege (`49–56`). IRQ supplies the exact current-mode bits and ordinary exception return (`irq.md:80–108`). |
| Distinguish ENTER from a request | The request wire's rising edge, VBlank observation, staging, pending NMI and firmware completion ENTER are separated (`system.md:62–66`). ENTER does not initiate entry from USER (`33`), and no ordinary cartridge callable is advertised (`64`). The revised companion shows how its supplied host-input timeline exercises the actual request. |
| Program CONTROL and interpret STATUS | Independent bits, complete processing order, current-mode admission, ignored bits, zero command readback and legal-stage effects are enumerated (`28–56`). FAULT capture and FAULT_PUBLISH are distinct (`34–35`, `146`). |
| Understand alignment/fault access behavior | Ordinary typed misalignment is explicitly checked before MMIO; aligned rejected port widths and read-only writes are distinct mapped bus faults (`191–201`). A newly raised mapped fault is not presented as a successful guest load of zero. MEMORY supplies the separate retained CODE/ADDR/ACCESS/ACK contract (`memory.md:715–787`). |
| Request reset | User availability, deferred/coalesced request, no reset-pending flag or zero-readback completion acknowledgement, consumption boundaries and reboot/not-all-zero-memory limits are stated (`system.md:209–213`). No fixed latency or invented polling handshake is needed. |
| Wait and read timing | TIME_MS units/truncation/wrap, central elapsed helper and one-wrap precondition, Q16 interpretation/truncation, whole-period vs remaining-cycle distinction, stopped-beam behavior and BIOS clock semantics are explicit (`217–238`). The example establishes VBlank delivery before HALT and rechecks elapsed time after every wake (`345–369`, `407–430`). IRQ describes the retained accepted-event indication and separate IE/MASK requirements (`irq.md:65–76`, `110–142`). |
| Use diagnostics | Codepoint-not-UTF-8 input, replacement while retaining raw readback, FLUSH0 publication, newline-not-flush behavior, queue capacity/overflow and absence of backpressure status are specified (`system.md:247–255`). The example supplies the exact nine raw bytes and snapshots readback before BIOS print writes the ports again (`440–475`). The companion identifies where the ordinary diagnostic text appears (`README.md:62–79`). |
| Interpret fault reports | Addresses/order, raw payload/domain, Cause mask/values, LuaReason values, stale BadAddress/LuaReason, synchronous vs asynchronous EPC and publication-not-atomic-snapshot are supplied (`system.md:131–185`).
