# Shared video publication: narrow cross-boundary facts

2026-10-17; master77216358a, clean before work. Internal facts, not public prose. This is the narrow consumer boundary required to interpret GPU/PCRTC publication, not a new physical fetch/arbitration model. No architecture document/PDF/runtime edits. Other device-specific facts remain GV/PV.

- VP01: All inspected installed render paths first execute commands up to the published `presentCommandCount`, then use the published PCRTC scanout description. Exact actual callers: `machine/ts/render/backend/software/gx_gpu.ts:49-56`; `machine/cpp/render/backend/software/gx_gpu.cpp:70-89`; `machine/ts/render/backend/webgl/gx_gpu.ts:3257-3264`; `machine/ts/render/backend/webgpu/gx_gpu.ts:2910-2915`; `machine/cpp/render/backend/gles2/gx_gpu.cpp:3793-3804`. These are frame-publication consumers, not a per-signal-pixel CPU-visible fetch deadline or a guest memory-release notification. The native range was read directly before accepting this sheet.
- VP02: Each path retains local-memory state between command batches and advances it by executing new commands; command serial changes reset the processed cursor, while snapshot serial changes also replace retained pixels. Sources: TS software `gx_gpu.ts:18-31`; native software `gx_gpu.cpp:26-47`; TS WebGL `gx_gpu.ts:3189-3202`; TS WebGPU `gx_gpu.ts:2621-2633`; native GLES2 `gx_gpu.cpp:3778-3790`. This does not say a configuration latch copied all VRAM bytes or that a CPU-visible IDLE bit retires display consumers. Backend paths are checked as implementation evidence only, not named in public hardware prose.
- VP03: The actual mirrored VBlank-begin route invokes GPU frame publication before input edge handling and before raising system IRQ_VBLANK. The separate tick-completion route follows publication/IRQ. Sources: `machine/ts/machine/runtime/vblank.ts:44-64`; `machine/cpp/machine/runtime/vblank.cpp:31-48`. Do not substitute a PCRTC VSINT or a stale pending VBlank flag for a fresh event after the final display-program write. No fixed request-to-handler latency follows from this order.
- VP04: Root reread the exact paired DMA service/finish/admission source behind committed DB03/DB05. Source payload is read one word at service, immediately written to its mapped target, followed by address/count update. Final DONE follows those mapped accesses; admission itself retains configuration, not a RAM payload copy. `machine/ts/machine/devices/dma/controller.ts:211-253,365-370,412-429`; `machine/cpp/machine/devices/dma/controller.cpp:142-183,289-294,336-350`. Thus a RAM staging source has a different lifetime from the VRAM words a later drawing command may sample. Full fault/readiness caveats remain DB06; this continuation does not infer delivery success from DONE.

- VP05: IRQ FLAGS/ACK/MASK use mapped aligned word addresses 08000000H/08000004H/08000008H; VBlank is bit2=4, separate from PCRTC bit1. MASK writes replace the raw mask, ACK clears selected pending bits without stopping future raises; raises OR a pending word independently of mask. Sources actual paired leaves `machine/ts/spec/bmsx/io.ts:3-8,214-216,363-364` / `machine/cpp/spec/bmsx/io.h:15-20,227-229,376-377`, base/word size `machine/ts/spec/bmsx/memory_map.ts:6,23,32` / `machine/cpp/spec/bmsx/memory_map.h:12,29,38`; paired controllers TS `machine/ts/machine/devices/irq/controller.ts:72-80,107-125`; native `machine/cpp/machine/devices/irq/controller.cpp:29-33,76-93`, maskable-line predicates TS controller:72-74 / native `machine/cpp/machine/devices/irq/controller.h:19` also read. Derived controlled fresh-publication wait (single cartridge owner, no supervisor/other writer): mask delivery before the final display write; ACK VBlank after that write; capture the callback sequence while still masked; re-enable VBlank; wait until callback sequence changes. A pending bit from an edge preceding the post-write ACK is discarded, not accepted as proof of publication. An edge after that ACK occurs after the final write. Combined with VP03 this supplies a fresh-after-write observation, not a hardware surface-release register, atomic multiword update, fixed latency or an exact count of all VBlank arrivals. The actual program/IRQ-entry must still execute and retain observations before authoring it as a complete route.
