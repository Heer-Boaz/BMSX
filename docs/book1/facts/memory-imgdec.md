## Narrow DMA/Memory boundary facts

Scope extension was solely source-byte lifetime and destination-write completion: DMA `ownsReadPort`/`ownsWritePort`, `admitBlock`, `onService`, `finishChannel`; Memory mapped 32-bit word read/write routes; paired WordFifo storage. No global memory map, allocator, bus-performance chapter or GPU owner was surveyed. Named callsites: paired DMA `ownsReadPort`, `ownsWritePort`, `admitBlock`, `onService`, `finishChannel`; Memory `readMappedDmaU32LE` / `readMappedBusU32LE` and `writeMappedDmaU32LE` / `writeMappedBusU32LE`; WordFifo `writeWord` / `pop`.

## Derived practical lifetime/completion checks

These are deductions from the cited owner bodies, **not runtime execution evidence**:

- **IB-D01:** Once an admitted CPU DATA write executes, the input word has been copied; IMGDEC need not retain/re-read that word's original guest storage. Starting/programming DMA, or block admission, is not such a copy: keep source words stable until their last scheduled DMA read (including repeated reads if read-address increment is disabled). For a whole source buffer with no other reader, input DMA DONE supplies the source-transfer boundary; IMGDEC DONE is decoder/output-drain completion, not required merely for source-byte reuse. `INPUT_WORDS_RECEIVED == INPUT_WORD_COUNT` likewise measures submissions, not decoder consumption. Caveat: IB-007 shows overfilled/misprogrammed DMA writes can be counted without FIFO insertion; DMA DONE alone is not a successful-decode proof. Basis: IB-005–008, IB-015–016.
- **IB-D02:** Do not infer fresh output from a DATA read alone: empty reads or CPU reads while DMA owns the port return retained/shared DATA. OUTPUT_REQUEST only promises its block threshold, not every arbitrary read count. Basis: IB-010–011.
- **IB-D03:** For a complete decoded output capture, the local necessary check is IMGDEC DONE rather than merely input-received/decoded progress or IRQ alone; fault raises the same IRQ boundary. If DMA drains into RAM, program the exact output word count from IB-009 and also require that DMA transfer's completion before using/reusing its destination buffer: IMGDEC DONE is emitted inside the DMA source read callback, whereas DMA's destination write and DONE follow in service order. This is source ordering, not a claim that firmware can run between those statements. Neither controller establishes downstream GPU execution/VRAM-visible completion. Basis: IB-008–013, IB-015–016.
- **IB-D04:** Repeated empty DATA reads after a normal successful termination can run the still-true completion check and call stop(DONE)/raise IRQ again; this body does not clear the completed predicates. Do not use extra reads as a harmless polling operation. Derived, not executed. Basis: IB-011–012.
- **IB-D05:** No transaction/rollback semantics exist in the inspected owner: a fault can leave partial output, while reset/new START discards queued internal output but cannot undo previously delivered words. Device-local reset alone does not establish that a separately admitted DMA block has stopped; DMA cancellation/reset/reuse protocol is **not extracted**. Basis: IB-013–016.

## Explicit missing/unproven contracts

1. **IB-G01:** No guest-visible output FIFO occupancy/read-count register exists in the examined map; the internal outputWordsRead state is not a progress read. A fault can leave retained output, but this extraction does not establish an exact software drain/recovery recipe after arbitrary partial command output. Register map/mapping boundary: `machine/ts/spec/bmsx/io.ts:138-148,183-192`; `machine/cpp/spec/bmsx/io.h:151-161,196-205`; `machine/ts/machine/devices/imgdec/controller.ts:139-148,550-553`; `machine/cpp/machine/devices/imgdec/controller.cpp:45-53,455-459`.
2. **IB-G02:** IRQ pending/mask/ACK semantics are not extracted; IMGDEC raises IRQ at its local DONE/fault stop. IRQ alone cannot classify success.
3. **IB-G03:** No guest ABORT operation was found in the examined IMGDEC spec/owner. System reset orchestration, admitted-DMA cancellation, and safe restart after an outstanding transfer are not established by this sheet.
4. **IB-G04:** No IMGDEC guest-data-memory window or free-allocation rule is introduced. Device-local FIFO/history arrays are retained internal storage, not a guest-addressable staging allocation. General RAM/ROM/cart mapping belongs to the memory chapter's separate owners.
5. **IB-G05:** Byte/halfword MMIO rules, output RAM address span/fault rules, exact GPU completion, full transfer programming examples and runtime acceptance are outside this extraction.

## Subsequent local-reset/admitted-DMA boundary

IB017: A fresh START or the IMGDEC reset operation alone does not cancel an already admitted DMA block. IMGDEC reset/start reset local stream state and/or update DMA request lines, not DMA live transfer state. Paired `setRequestLines` calls `arbitrate`; its first branch returns while any block is active. The existing captured block still uses service's captured addresses/count/control and perword reads/writes. Sources TS `machine/ts/machine/devices/imgdec/controller.ts:151-185,298-307`, `machine/ts/machine/devices/dma/controller.ts:171-178,211-253,386-389`; C++ `machine/cpp/machine/devices/imgdec/controller.cpp:56-90,199-208`, `machine/cpp/machine/devices/dma/controller.cpp:101-108,142-183,310-313`. This narrower source extension supports the exact public local-reset warning, not whole-machine reset, a general DMA cancellation mechanism or an arbitrary restart/recovery policy.
