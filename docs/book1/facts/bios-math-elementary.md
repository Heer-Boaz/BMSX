## E0. Installation and local versus public dependencies

- The BIOS entry first requires `base`, later requires `os`, then assigns the returned math module to the public global `math`. This is the install owner, not just an export-name inventory. Sources: `machine/bios/main.lua:4-12`.
- `math.lua` unconditionally starts by requiring `math/sin`, even when a caller will use only an elementary function. None of the elementary function bodies in this packet calls that imported function. The import is a module-load dependency, not per-elementary-call trigonometric work. Sources: `machine/bios/math.lua:1`, `27-90`, `281-314`.
- The math module returns an ordinary table containing the local closures/constant values: `abs` (350), `ceil` (354), `floor` (358), `fmod` (359), `huge` (360), `max` (362), `maxinteger` (363), `min` (364), `mininteger` (365), `modf` (366), `pi` (367), `round` (371), `sign` (372), `tointeger` (376), `type = type_name` (377), `ult` (378). Source: `machine/bios/math.lua:349-379`.
- `trunc` is private, not an export. `fmod` and `modf` use the local `trunc`; `tointeger` uses local `trunc` and local `huge`; `type_name` uses local `tointeger`; `ult` uses local `u32_mod`. None of these nested calls goes through a public `math` table field. The bodies of `tointeger` and `type_name` refer to the public/global `type`; `min` and `max` refer to public/global `error` and `select`, not module-local aliases. Sources: `machine/bios/math.lua:13`, `23`, `27-32`, `55-90`, `281-304`.
- The initialized `base` module captures `__bmsx_type`, `__bmsx_select`, and `__bmsx_error` as `vm_type`, `vm_select`, `vm_error`, and installs those as `type`, `select`, `error`. These are the dependencies used for the normal installed-environment facts below; rebinding those public dependencies is not a math-local capability or validation guarantee. Sources: `machine/bios/base.lua:3`, `8-9`, `205-214`.

## E1. Shared representation / operator facts needed to read the bodies

- There is one guest numeric kind here, not separately stored integer/float subtypes. TS guest slots use `ValueTag.Number` with numeric scalar data; C++ uses a `uint64_t Value` with untagged binary64 number bits and NaN-boxed non-number tags. `math.type` below is a BIOS classification computed from the value, not inspection of an integer subtype. Sources: `machine/ts/machine/cpu/value.ts:8-18`, `44-50`; `machine/ts/machine/cpu/value_slots.ts:128-130`, `181-185`; `machine/cpp/machine/cpu/value.h:29-40`, `95-110`, `132-145`.
- Write `D(a,b)` for the actual `//` helper: compute binary floating `q = a / b`, `t = trunc_host(q)` (`Math.trunc` in TS; `std::trunc` in C++), then return `t > q ? t - 1 : t`. It has no denominator-zero branch, finite/range check, integer-width conversion, or Lua error branch. This is an equation for the helper actually called, not an assertion of exact real-number floor arithmetic. Sources: `machine/ts/spec/blua32/numeric.ts:1-5`; `machine/cpp/spec/blua32/numeric.h:7-11`; dispatch to it: `machine/ts/machine/cpu/cpu.ts:2551-2586`, `machine/cpp/machine/cpu/cpu_dispatch.inl:208-213`.
- Write `T(x)` for the BIOS private `trunc`: if guest comparison `x < 0` is true, return `-D(-x,1)`; otherwise return `D(x,1)`. This is truncation toward zero for ordinary finite numeric values, implemented with the shared floor-divide path. It is not a machine-word or signed-integer encoder. Source: `machine/bios/math.lua:27-32`, plus the paired `D` owners above.
- Write `M(a,b)` for actual `%`: TS starts with JS `a % b`; C++ starts with `std::fmod(a,b)`. If `r > 0 ? b < 0 : r < 0 && b > 0`, add `b`; otherwise return `r` unchanged. There is no denominator-zero or non-finite error branch and no zero-sign normalization. Sources: `machine/ts/spec/blua32/numeric.ts:7-13`; `machine/cpp/spec/blua32/numeric.h:13-19`; dispatch: `machine/ts/machine/cpu/cpu.ts:2551-2583`, `machine/cpp/machine/cpu/cpu_dispatch.inl:199-206`.
- Addition/subtraction/multiplication/division and unary minus are numeric datapaths, not calls to `tonumber`: TS `readRKNumber` / `getNumber` supplies numeric scalar values for number tags and NaN for other guest tags; C++ directly reinterprets the raw word as a double (`asNumber`), so its NaN-boxed non-number words feed NaN into arithmetic. Results are stored as guest numbers; NaNs are canonicalized by number storage. Consequently decimal-looking guest strings are not parsed/coerced into their decimal values by these math arithmetic expressions, and non-number arithmetic has no argument-type Lua error branch in these owners. Sources: `machine/ts/machine/cpu/cpu.ts:2551-2586`, `2659-2662`, `3589-3596`; `machine/ts/machine/cpu/value_slots.ts:128-130`, `181-185`; `machine/ts/machine/cpu/value.ts:48-50`; `machine/cpp/machine/cpu/cpu_dispatch.inl:171-213`, `308-312`; `machine/cpp/machine/cpu/value.h:95-145`.
- Numeric `<` and `<=` are the host double comparisons. String/string `<` and `<=` also exist. Every other tag pairing sets the ordering result to false; these dispatchers do not throw a mixed-type ordering error or invoke `__lt`/`__le`. In particular, ordering a guest string/table/boolean/nil/function/thread against numeric zero is false. Sources: `machine/ts/machine/cpu/cpu.ts:2701-2735`, `2812-2847`; `machine/cpp/machine/cpu/cpu_dispatch.inl:356-384`.
- The string-order substrates differ: TS calls `utf8Compare` over its string pool text; C++ compares stored `std::string` text. `utf8Compare` compares UTF-16 code units with explicit supplementary/BMP ordering adjustment. This packet does not claim or audit parity for every malformed/raw-byte string state. It records each reached owner and does not turn that difference into an unverified universal shared ordering contract. Sources: `machine/ts/machine/cpu/cpu.ts:2727-2731`, `2838-2842`; `machine/ts/common/utf8.ts:36-55`; `machine/cpp/machine/cpu/cpu_dispatch.inl:362-363`, `377-378`.
- Equality distinguishes different guest tags; numeric equality is the numeric scalar comparison (so NaN is unequal to itself and the two numeric zero signs compare equal). Nil equals nil. Sources: `machine/ts/machine/cpu/cpu.ts:3546-3586`; `machine/cpp/machine/cpu/cpu_dispatch.inl:341-353`.
- The installed public `type` dependency returns `number` for the guest numeric tag/representation, including numeric NaN and infinities; the other guest tags are reported as `nil`, `boolean`, `string`, `thread`, `table`, or `function`. Sources: `machine/ts/machine/cpu/cpu.ts:3604-3608`, `4194-4196`; `machine/ts/machine/cpu/value.ts:149-167`; `machine/cpp/machine/cpu/cpu.cpp:1666-1668`; `machine/cpp/machine/cpu/value.h:481-494`.
- Missing fixed parameters are filled with guest nil; fixed-arity functions do not retain surplus arguments; vararg functions retain every surplus value, including explicit nils. No automatic arity exception is added by frame setup. Sources: `machine/ts/machine/cpu/cpu.ts:3272-3296`; `machine/cpp/machine/cpu/cpu.cpp:3017-3042`.

## E3. Exact operations, branches, conversions, and reached special cases

### E3.1 `abs`

- Equation: if `value < 0`, return unary `-value`; otherwise return `value` itself. The nonnegative arm does not reconstruct or convert the value. For ordinary numeric input this changes a negative finite value or negative infinity to its positive negation. NaN, positive infinity, +0, and -0 all fail `< 0` and return unchanged. In particular, -0 is preserved, not forced to +0. Source: `machine/bios/math.lua:33-38`; numeric/unary/ordering owners: E1.
- All non-number guest values fail the comparison against numeric zero and are returned unchanged, including nil on a missing call. There is no numeric-string conversion or explicit error. Source: `machine/bios/math.lua:33-38`; paired mixed-tag ordering: `machine/ts/machine/cpu/cpu.ts:2724-2732`, `machine/cpp/machine/cpu/cpu_dispatch.inl:359-364`.
- Units: no angular/fixed-point scaling or word conversion; when numeric it operates on the supplied numeric quantity. Source: entire body `machine/bios/math.lua:33-38`.

### E3.2 `floor`, `ceil`, and `round`

- `floor(x)` returns `D(x,1)` with no preceding branch. `ceil(x)` returns `-D(-x,1)` with no preceding branch. Neither consults maxinteger/mininteger or casts to a word. Sources: `machine/bios/math.lua:40-46` and paired `D`/unary owners in E1.
- For numeric infinities those equations return the corresponding signed infinity; for NaN they produce numeric NaN. For numeric +0/-0 they preserve the input zero sign in both floor and ceil. These are consequences of the exact double/trunc/unary equations, not runtime examples. Sources: `machine/bios/math.lua:40-46`; `machine/ts/spec/blua32/numeric.ts:1-5`, `machine/cpp/spec/blua32/numeric.h:7-11`; unary: `machine/ts/machine/cpu/cpu.ts:2659-2662`, `machine/cpp/machine/cpu/cpu_dispatch.inl:308-312`.
- `round(x)` tests `x >= 0`. On true it returns `D(x + 0.5, 1)`; otherwise it returns `-D((-x) + 0.5, 1)`. For ordinary small finite exact-half cases this is half-away-from-zero, but the actual addition/division/truncation equation—not an ideal all-magnitudes rounding guarantee—is the contract available from source. In particular the `+0.5` arithmetic is itself floating arithmetic and there is no range/overflow correction. Source: `machine/bios/math.lua:48-53`; paired arithmetic and `D`: E1.
- Both zero signs enter the nonnegative round arm, which returns +0. For negative finite input, a +0 result of `D((-x) + 0.5, 1)` is negated to -0; no claim that every real magnitude below half must reach that zero result overrides floating addition. Positive/negative infinity retain their infinity sign. NaN fails the nonnegative comparison and the negative-arm arithmetic yields NaN. Source equation: `machine/bios/math.lua:48-53`; paired comparison/arithmetic/trunc owners: E1. These are source-derived special-value consequences only.
- For any non-number input, including omitted/nil or numeric-looking strings, floor and ceil reach numeric NaN datapaths. Round's nonnegative comparison is false for non-number versus zero, and its negative-arm arithmetic likewise yields numeric NaN. No explicit BIOS error or `tonumber` conversion occurs. Sources: `machine/bios/math.lua:40-53`; mixed ordering and arithmetic decoding owners in E1.
- Units: the functions remove/choose a whole-number portion at unit spacing in the supplied numerical scale; they do not rescale angles or fixed-point units and their result representation remains the single guest number kind. Sources: `machine/bios/math.lua:40-53`; E1 representation owners.

### E3.3 `fmod`

- Exact evaluation order/equation: compute `left / right`, pass that value to private `T`, multiply the resulting number by `right`, then subtract the product from `left`: `left - (T(left / right) * right)`. This is not a call to shared `%`/`M`, host `fmod`, or public `math.modf`. Source: `machine/bios/math.lua:55-57`; `T`: `27-32`; paired `/`, `*`, `-`, `D`: E1.
- There is no branch/check for zero divisor, infinity, NaN, integer bounds, or operand types. Zero divisor and any numeric infinity operand lead through the literal floating equation to NaN; NaN also propagates. Finite input does not imply a finite mathematical remainder: division can overflow before truncation; no replacement algorithm repairs that. These are equation-derived consequences, not executed examples or accuracy claims. Sources: `machine/bios/math.lua:55-57`, `27-32`; paired datapaths E1.
- Either non-number operand (including either missing operand) reaches arithmetic NaN, so the result is one numeric NaN, not nil or an argument-type exception. Numeric strings are not parsed. Sources: `machine/bios/math.lua:55-57`; paired numeric decoding E1.
- For a numeric zero left operand and finite nonzero right operand, the equation subtracts the same-signed zero product and yields +0, including a -0 left operand; it does not explicitly preserve the numerator zero sign. Source equation: `machine/bios/math.lua:55-57`, with `T` at `27-32` and the paired floating operations in E1.
- Units: subtraction returns in the left/right numerical scale used by the expression; no angular conversion, word conversion, or integer subtype is introduced. Source: `machine/bios/math.lua:55-57`.

### E3.4 `modf`

- Compute `integer = T(value)` once; return exactly `(integer, value - integer)` in that order. It neither calls public `math.floor` nor requests a separate integer representation. Source: `machine/bios/math.lua:59-62`, private `T`: `27-32`.
- For ordinary finite numeric input, the first component is truncation toward zero and the second is the floating residual from that chosen first component; this is not a positive-fraction floor decomposition for negative values. There is no maxinteger/mininteger range gate. Source: `machine/bios/math.lua:27-32`, `59-62`.
- Numeric +infinity returns `( +infinity, NaN )`; numeric -infinity returns `( -infinity, NaN )`; NaN returns `(NaN, NaN)`. For +0 and -0, the first result preserves the supplied zero sign and the second result is +0. All are equation-derived from `T` and `value - integer`, without explicit special-case branches. Sources: `machine/bios/math.lua:27-32`, `59-62`; paired floating owners E1.
- Nonnumeric/missing input makes `T` return numeric NaN and the subtraction return numeric NaN: exactly two NaN numbers, not two nils and not an argument-type error. Sources: `machine/bios/math.lua:27-32`, `59-62`; paired ordering and arithmetic decoding E1.
- Units: both components use the original supplied numeric scale; no conversion of units. Source: `machine/bios/math.lua:59-62`.

### E3.5 `min` / `max` and the reached `select` / `error` behavior

- `min(first, ...)`: if `first == nil`, call global `error('min expects at least one argument.')`; otherwise set `result = first`. Source-level loop: `for index = 1, select('#', ...) do`; each body stores the first returned value from `select(index, ...)` in `value`; replace result only when `value < result`; return result. Source: `machine/bios/math.lua:64-76`.
- `max(first, ...)` is structurally the same but its explicit message is `max expects at least one argument.` and replacement condition is `value > result`. Source: `machine/bios/math.lua:78-90`.
- First-argument nil is rejected even if later arguments are nonnil. A single nonnil first argument is returned as-is. No numeric conversion, per-tail nil rejection, type homogenization, or metatable comparison is performed. Comparable ties keep the earlier selected value because replacement is strict. Sources: `machine/bios/math.lua:64-90`; paired ordering E1.
- Numeric candidates use numeric order. A later NaN does not replace an existing numeric result; an initial NaN remains the result because comparisons with it are false. Numeric infinities order via the same comparison. Equal +0/-0 arguments do not replace one another, preserving whichever zero sign was first selected. Sources: `machine/bios/math.lua:68-75`, `82-89`; numeric ordering E1.
- String/string candidates take the string comparison paths stated in E1; the returned value is an original string argument, not a number. A later value whose tag is incomparable with the current result is ignored. An initial nonnil boolean/table/function/thread cannot be replaced by these ordering dispatchers; an initial number ignores non-number candidates and an initial string ignores non-string candidates. Explicit nil tail arguments count as arguments but cannot replace the nonnil result. Sources: `machine/bios/math.lua:64-90`; paired comparison dispatch `machine/ts/machine/cpu/cpu.ts:2701-2735`, `machine/cpp/machine/cpu/cpu_dispatch.inl:356-369` (with operands reversed for source `>`); string substrate limitation E1.
- Normal installed `error` raises the supplied string value by throwing a guest `LuaThrownValueError`; it is not a math-local formatted argument-number exception or level-adjusted standard-Lua message. No subsequent return is executed on that normal throw path. Sources: math error calls `machine/bios/math.lua:65-67`, `79-81`; installation `machine/bios/base.lua:9`, `214`; TS `machine/ts/machine/cpu/cpu.ts:4370-4380`; C++ `machine/cpp/machine/cpu/cpu.cpp:2225-2228`.
- The called `select('#', ...)` returns `args.length - 1` / `args.size() - 1`, i.e. the exact vararg count passed to it, retaining explicit nil tails. The `'#'` selector path returns immediately. Sources: `machine/ts/machine/cpu/cpu.ts:4286-4299`; `machine/cpp/machine/cpu/cpu.cpp:2152-2158`; retained varargs E1.
- The called `select(index, ...)` does not produce just one selected value internally. It converts numeric selector to signed 32-bit (`selectorScalar | 0` / `toI32`), translates a negative start to `count + start + 1`, then walks through `count`, appending every argument whose index is at least 1 and less than the supplied argument count. For positive unwrapped source indices this produces the whole suffix starting at that index. Local single-variable assignment consumes only its first result after the builtin has computed the suffix. A nonnumeric selector errors, but normal BIOS `index` is supplied by the numeric loop; the selector's signed-word conversion is still part of the reached owner, so do not erase it in an unbounded idealized vararg contract. Sources: `machine/ts/machine/cpu/cpu.ts:4301-4317`; `machine/cpp/machine/cpu/cpu.cpp:2161-2173`; C++ selector word conversion `machine/cpp/machine/cpu/value.h:199-229`; result truncation after generation: `machine/ts/machine/cpu/cpu.ts:3841-3861`, `3421-3438`; `machine/cpp/machine/cpu/cpu.cpp:1876-1892`, `3127-3139`; math callsite `machine/bios/math.lua:69-70`, `83-84`.
- Units: no conversion or normalization is performed; selection returns a supplied argument in its own representation. Source: `machine/bios/math.lua:68-75`, `82-89`.

### E3.6 `tointeger`

- First short-circuit guard: if `type(value) ~= 'number'` OR `value ~= value` OR `value == huge` OR `value == -huge`, return exactly one nil. Therefore missing/nil, every non-number guest tag (including numeric-looking strings), numeric NaN, and either numeric infinity take the rejection branch with the normal installed type dependency. Source: `machine/bios/math.lua:281-284`; installed `type` and equality owners E0/E1.
- If the guard passes, compute private `integer = T(value)`. Return that numeric result only if `integer == value`; otherwise return one nil. There is no truncation-success result for a fractional value: the truncation result is tested for equality before it is exposed. Source: `machine/bios/math.lua:285-290`; private `T`: `27-32`.
- No bound check references `mininteger` or `maxinteger`; no 32-bit or 64-bit integer encoding occurs. A finite representable numeric value whose `T(value)` equals itself is accepted even outside the published integer constants' range. Numeric -0 is accepted and retains its zero sign through `T`; its equality test succeeds because numeric zeros compare equal. Sources: complete guard/body `machine/bios/math.lua:281-290`, `27-32`; constant definitions `11-12`; paired equality and representation E1.
- Units/return representation: acceptance preserves the same numeric scale and returns a guest number, not a machine word or separate integer subtype. Source: `machine/bios/math.lua:285-287`; numeric result representation E1.

### E3.7 `type` (exported local `type_name`)

- If global `type(value) ~= 'number'`, return one nil. Otherwise call the captured local `tointeger(value)`: if it is nonnil, return literal string `integer`; otherwise return literal string `float`. The public export name is `type`, but this does not recursively call `math.type`. Sources: `machine/bios/math.lua:292-300`, `377`.
- With the initialized public type dependency, missing/nonnumeric values (including numeric-looking strings) return nil; finite numeric whole values accepted by `tointeger`, including -0 and representable whole values outside the integer constants, classify as `integer`; finite numeric fractions, infinities, and NaN classify as `float`. This is a computed predicate over the single number representation, not a stored subtype or proof of word convertibility. Sources: `machine/bios/math.lua:281-300`; E1 type/representation owners.
- Captured-call consequence: replacing public table field `math.tointeger` does not change which local closure this body calls; its `type` dependency remains a nonlocal/global reference in source. Sources: `machine/bios/math.lua:281-300`, `376-377`.

### E3.8 `ult`

- Exact expression: `(left % u32_mod) < (right % u32_mod)` with captured `u32_mod = 4294967296.0`. It uses `M` for each operand, then numeric `<`. There is no integrality test, truncation, `& 0xffffffff`, or word conversion in this body. Sources: `machine/bios/math.lua:23`, `302-304`; paired `M`/comparison E1.
- For integer numeric inputs it compares their floating modulo-2^32 residues; it is not an unsigned comparison across the `maxinteger`/`mininteger` constants' full numerical interval. Fractional numeric inputs also pass directly through modulo and are compared without integer truncation. Do not substitute standard Lua integer-width unsigned-order semantics for this expression. Sources: `machine/bios/math.lua:23`, `302-304`; `machine/ts/spec/blua32/numeric.ts:7-13`; `machine/cpp/spec/blua32/numeric.h:13-19`.
- Negative residues are adjusted by adding the positive modulus when `r < 0`; zero residues preserve the remainder's zero sign, and equality of either zero sign does not produce a strict-less result. Floating arithmetic is still used: the body makes no exact-residue, exact-range, or all-magnitudes accuracy repair/guarantee. Sources: `machine/bios/math.lua:302-304`; paired modulo helper E1; numeric comparison E1.
- An infinity or NaN operand makes its modulo result NaN, and strict `<` is false. A non-number/missing operand also decodes to NaN on modulo; the result is false, not nil or a type/arity exception. Sources: `machine/bios/math.lua:302-304`; paired `%`, arithmetic decoding, and numeric ordering E1.
- Units: comparison operates on modulo-2^32 numerical residues without scale conversion; the returned boolean carries no numeric units. Sources: `machine/bios/math.lua:23`, `302-304`.

### E3.9 `sign`

- Test `value > 0`; true returns literal numeric 1. Else test `value < 0`; true returns literal numeric -1. Else return literal numeric 0. No subtraction/division, magnitude computation, or numerical conversion occurs. Source: `machine/bios/math.lua:306-314`.
- Positive/negative infinities follow their positive/negative comparison branches. Both numeric zero signs and numeric NaN reach literal 0; no -0 result is preserved. All non-number guest tags, including missing/nil and numeric strings, fail both mixed-type comparisons against zero and return numeric 0. No explicit error occurs. Sources: `machine/bios/math.lua:306-314`; paired ordering E1.
- Units: returns an unscaled dimensionless numeric branch marker; it does not preserve input units. Source: literal-return body `machine/bios/math.lua:306-314`.

## E5. Variable work, cost boundaries, and limits of these facts

- `abs`, `floor`, `ceil`, `round`, `fmod`, `modf`, `sign`, `tointeger`, `type`, and `ult` have bounded source control flow, no input-magnitude normalization loops, and no per-input collection traversal. `fmod`/`modf` each add one private `T` call; `tointeger` adds `type` and `T` only on the corresponding guard path; `math.type` first calls public `type` and for numbers calls private `tointeger`, which itself calls public `type` again. Sources: `machine/bios/math.lua:27-62`, `281-314`.
- `min`/`max` are the variable-work exceptions. For `n = select('#', ...)` source tail arguments, their source loops request one candidate per index, but every candidate call forwards all `...` again and the normal select builtin walks/appends the selected suffix before caller result adjustment. In the ordinary positive, signed-32-bit selector interval this creates n comparisons, repeated n-value vararg forwarding, and suffix-result production of `n + (n-1) + ... + 1` values: quadratic data movement/work, not an O(n) implementation just because the comparison count is linear. This is a static source/owner inference, not a benchmark and not a revalidation of unresolved general numeric-loop semantics. Sources: `machine/bios/math.lua:69-74`, `83-88`; vararg materialization `machine/ts/machine/cpu/cpu.ts:2896-2916`, `machine/cpp/machine/cpu/cpu_dispatch.inl:475-487`; select loops `machine/ts/machine/cpu/cpu.ts:4304-4317`, `machine/cpp/machine/cpu/cpu.cpp:2164-2173`; produce-before-truncate `machine/ts/machine/cpu/cpu.ts:3841-3861`, `3421-3438`, `machine/cpp/machine/cpu/cpu.cpp:1876-1892`, `3127-3139`.

Do not claim constant-time string min/max or full malformed-string parity here. Sources: `machine/ts/common/utf8.ts:36-55`; `machine/cpp/machine/cpu/cpu_dispatch.inl:362-363`; loop sources above.

TS `BuiltinResults` grows its `ValueSlots` geometrically and copies prior contents; C++ `BuiltinResults` grows an owned `Value[]` geometrically and copies prior contents. This is capacity-dependent allocation/copying at runtime-owner boundaries, not a fresh arbitrary math-local table per iteration.
