**Raw representation.** Command/slot/source-address/length/transfer/control/status values remain raw register words: TS command latch/FIFO use `Uint32Array`; C++ parameters are `u32` words. A bound source is a byte view (TS backing `Uint8Array` plus offset/length/slot; C++ `Span<const u8>` plus slot), not a copied payload. Private sample RAM is a separate byte array. Sources: TS `machine/ts/machine/devices/audio/command_latch.ts:25–45`, `command_fifo.ts:17–22,52–58`, `source.ts:21–40`, `sample_memory.ts:10–12`; C++ `machine/cpp/machine/devices/audio/command_fifo.cpp:33–38`, `source.h:9–12`, `source.cpp:5–17`, `sample_memory.h:25–27`.

## Source-derived facts

**AB01 — Private source space is not CPU main RAM.** APU owns 512 KiB sample RAM; `0x40000000` is its voice-source address base/tag. `bindSource` resolves an address in that private extent to its own backing bytes. Transfer ADDRESS instead selects a private-RAM byte offset, masked to the RAM size and rounded down to a word boundary; transfer increments wrap within that private RAM. This does not expose a CPU pointer at `0x40000000`. CPU mapped U32 reads resolve the normal map and miss beyond cart-bus end; upload/download use the APU transfer port. Sources: paired APU leaf TS `machine/ts/spec/audio/apu.ts:6–16`, C++ `machine/cpp/spec/audio/apu.h:10–19`; TS sample RAM `sample_memory.ts:20–46`, transfer `sample_transfer.ts:142–155,201–213`; C++ sample RAM `sample_memory.cpp:17–38`, transfer `sample_transfer.cpp:113–138,195–207`; CPU map TS `machine/ts/machine/memory/memory.ts:544–570`, C++ `machine/cpp/machine/memory/memory.cpp:434–460`, paired map leaves TS `machine/ts/spec/bmsx/memory_map.ts:3–21`, C++ `machine/cpp/spec/bmsx/memory_map.h:9–27`.

**AB02 — Direct sampled voices bind private RAM or installed ROM, not main-RAM BSS.** Non-generator binding first checks private sample RAM, otherwise binds an installed system-ROM or cartridge-ROM byte extent. The Memory binder has no main-RAM source case; a linked ordinary BSS address is not a direct sampled-voice source. Main RAM may instead be upload staging or download destination through DMA. Cartridge selection is read when PLAY executes/binds (and again on an active source-window rebind), not captured into the queued CMD descriptor. The bound view then records that slot. A generator takes the empty byte-view branch and needs no sample payload. Sources: TS `sample_memory.ts:20–38`, `command_executor.ts:146–158,201–236`; C++ `sample_memory.cpp:17–30`, `command_executor.cpp:107–119,162–193`; Memory TS `machine/ts/machine/memory/memory.ts:708–718`, C++ `machine/cpp/machine/memory/memory.cpp:623–633`; slot forwarding TS `machine/ts/machine/devices/cartridge/controller.ts:200–202`, C++ `machine/cpp/machine/devices/cartridge/controller.cpp:146–153`. No media-replacement/banking-lifetime guarantee is extracted.

**AB03 — CMD captures parameters, not source bytes, and execution is distinct.** Accepted supported commands copy all 21 staging words into the command FIFO and clear the staging latch. FIFO pop later supplies those words to the executor; PLAY then binds the source view and builds the voice. A later staging write does not edit an already queued entry, but changing backing sample bytes before its PLAY executes can affect that future voice. STOP is queued by the same ingress, not completed merely by the CMD write. Sources: TS `command_ingress.ts:25–37`, `command_fifo.ts:52–84`, `command_executor.ts:82–86,146–158`, controller `controller.ts:186–189`; C++ `command_ingress.cpp:23–37`, `command_fifo.cpp:33–65`, `command_executor.cpp:42–46,107–119`, controller `controller.cpp:93–96`; parameter count TS APU leaf `:29`, C++ `:36`.

**AB04 — A voice keeps a byte view and reads later; there is no whole-source snapshot.** Voice construction retains the backing source bytes/data offset and copies playback-description words; PCM playback reads sample bytes through that retained backing view. BADP also fetches later compressed bytes, but keeps decoder/decoded-frame state; do not promise every mutation is immediately reread. For unchanged intended playback, preserve required bytes through all remaining playback/loop/seek/future uses, not merely through PLAY acceptance. Sources: TS `output.ts:452–489,532–546`, `pcm_decoder_hot_path.ts:4–8`, `badp_decoder_hot_path.ts:69–101,155–166`; C++ `output.cpp:375–418,470–493`, `pcm_decoder_hot_path.h:8–12`, `badp_decoder_hot_path.h:46–56,154–176`. This is a source-derived lifetime caution, not measured mutation timing or an invitation to stream over a live decoder.

**AB05 — Selected-slot source words are live programming, not staging.** The selected-slot write synchronizes current audio, writes that slot's register word, and for source-buffer fields rebinds/rebuilds the active voice using the now-current full slot description. There is no atomic multiword replacement edge. If that rebind fails, that voice is stopped/deactivated and a source-range fault is raised. By contrast a failed new PLAY binding returns with a fault before replacing the existing slot. Sources: TS `command_executor.ts:115–120,152–158,201–236`, `source.ts:47–61`; C++ `command_executor.cpp:75–81,113–119,162–193`, `source.h:19–28`. Do not teach intermediate source-field writes as a safe transactional update or a fault as a global release of sources.

**AB06 — Pause, loop and fade do not release the source.** Pause stops rendering that resident voice but retains it for RESUME; its slot remains non-idle/active in the slot bank. A loop wraps and continues reading instead of ending at the first pass. STOP with a positive fade does not itself immediately clear the resident voice; pending fade can require its source until that slot ends, but source exhaustion can end a nonlooping voice before the fade completes. Renderer-active and resident are not synonyms: pause clears renderer-active while the bank remains non-idle and the resident source view is retained; STOP with no fade, when executed, clears active/resident and clears the selected slot bank. Natural/fade end clears the ended voice and bank and emits the ended event with its source address. Sources: TS `command_executor.ts:161–192`, `slot_bank.ts:35–57`, `output.ts:232–249,332–352,403–436`, `active_slots.ts:42–64`; C++ `command_executor.cpp:122–153`, `slot_bank.cpp:19–42`, `output.cpp:144–160,260–267,322–359`, `active_slots.cpp:35–56`.

**AB07 — An END/cleared slot bit is not “all source buffers free”.** The end path stops that slot only. Other slots can share the same bytes, FIFO entries can contain later PLAYs, and staged/future programming can intentionally name them again; private-RAM transfers are a separate engine. Reuse requires accounting for every such use under the program's ownership, not merely one end event. APU STATUS BUSY is derived from nonzero slot-active mask OR a nonempty command FIFO; it is not the transfer-busy bit and does not account for an unsubmitted future staging intention. Sources: end/slot sources AB06; FIFO capture AB03; TS `status_register.ts:21–29`, C++ `status_register.cpp:25–39`; transfer independence AB09–AB11. This is a derived program-discipline requirement, not automatic reference counting, isolation or allocation permission.

**AB08 — Fault acknowledgment is not a stop/reset; reset is destructive.** APU fault ACK clears only fault code/detail/status. It does not flush command/transfer FIFOs or stop all voices. Actual new-PLAY failure versus active-rebind failure is distinguished in AB05, so a generic FAULT bit cannot certify no readers remain. APU reset clears command FIFO, sample RAM, slot bank, transfer state, output playback, fault/staging/event state; it is not completion or preservation of old sample data. Sources: TS `controller.ts:105–108,124–133`, `sample_memory.ts:16–18`, `sample_transfer.ts:54–67`, device status `machine/ts/machine/devices/device_status.ts:46–55`; C++ `controller.cpp:72–81`, `sample_memory.cpp:13–15`, `sample_transfer.cpp:23–36`, device status `machine/cpp/machine/devices/device_status.cpp:53–63`. Reset/media/supervisor orchestration beyond this APU owner is withheld.

**AB09 — Upload admission and private-RAM commit are separate.** CPU DATA in MANUAL_WRITE writes the private-RAM word immediately. DMA DATA in DMA_WRITE captures the word in a 16-word FIFO; the block-end edge schedules a batch. The batch later pops words into private RAM and advances its current private offset. Thus DMA's final mapped-port write and DMA DONE are not necessarily the last private-RAM commit. The DMA APU_WRITE request is asserted when DMA_WRITE FIFO is empty; full FIFO push returns without adding a word. Use the owning DMA/APU request protocol, not an assumed FORCE delivery guarantee. Sources: TS APU leaf `:9,14–15`; `sample_transfer.ts:151–177,201–236,245–265`; C++ leaf `:13,16–17`; `sample_transfer.cpp:134–149,179–185,195–247`; DMA final writes/finish TS `machine/ts/machine/devices/dma/controller.ts:229–253,365–370`, C++ `machine/cpp/machine/devices/dma/controller.cpp:159–183,289–294`.

**AB10 — Bounded upload completion check.** After the one intended DMA upload has completed, with no competing transfer-port/configuration writer, read synchronized APU STATUS and wait until TRANSFER_BUSY (bit 10, `0x400`) clears before treating the private upload as committed or starting a voice over those bytes. That bit reflects scheduled transfer words, distinct from voice/command BUSY. STATUS reads synchronize due transfer batches before reporting it; DMA_WRITE service reschedules until its queued words are drained. This is not automatic isolation or proof of correct data/absence of faults; retain the DMA/result/fault checks of the owning operation. Sources: TS APU leaf `:58–66`, `sample_transfer.ts:85–91,135–139,201–236`, `service_clock.ts:118–126`, `status_register.ts:21–29`; C++ APU leaf `:65–73`, `sample_transfer.cpp:54–71,166–170,195–235`, `service_clock.cpp:156–164`, `status_register.cpp:25–39`.

**AB11 — Download prefetch and transfer reprogramming need their own boundary.** DMA_READ batch service copies private-RAM words into FIFO; DMA DATA reads consume them. At block end the engine can schedule refill even after the requested DMA transfer is done, so download DMA DONE is not proof the sample-transfer engine is stopped. Changing transfer mode (including STOP=0) cancels scheduled work, clears FIFO/carry and updates requests; it does not undo private-RAM writes already committed. Writing TRANSFER_ADDRESS changes current offset immediately; pending FIFO words do not carry separate destination addresses. Do not reprogram an upload while its commit is pending. Sources: TS `sample_transfer.ts:142–168,182–216,218–243,261–265`; C++ `sample_transfer.cpp:113–131,153–176,195–248`; STOP mode paired APU leaves TS `:12–16`, C++ `:15–19`. Download completion and voice-source release remain different questions.

## Reader-directed precision extension

**AB13 — Name the per-slot notification, not an invented END register.** The paired APU leaves define SLOT_ENDED event kind (APU_EVENT_SLOT_ENDED=1). Audio advance takes the renderer's ended mask, saves that slot's source address, clears that slot, and emits SLOT_ENDED. The ordinary immediate no-fade STOP path clears/stops the slot without emitting an event. Use SLOT_ENDED in public prose; a zero-fade STOP cannot be awaited as if it always generated that notification. Sources: `machine/ts/spec/audio/apu.ts:83–84`, `machine/cpp/spec/audio/apu.h:90–91`; `machine/ts/machine/devices/audio/active_slots.ts:42–45,57–64`, `machine/cpp/machine/devices/audio/active_slots.cpp:35–38,50–57`; immediate STOP `machine/ts/machine/devices/audio/command_executor.ts:161–175`, `machine/cpp/machine/devices/audio/command_executor.cpp:122–136`. Actual emit publishes kind/slot/source/sequence and raises APU IRQ: paired event_latch TS:56–69 / C++:38–51. No new event count/address is required in the memory prose.

**AB14 — Fade is not a safe source-length clamp.** At render entry, an out-of-bounds nonloop cursor ends regardless of pending fade. Inside the render loop, the fade branch decrements/completes fade instead of taking the normal post-frame source-boundary branch; nonloop cursor can therefore advance outside its declared extent before fade completion. Do not summarize this as safe automatic termination at the source end. Derived programming caution: keep a nonlooping fade within its remaining source data, or provide a valid loop for the fade duration. Sources: `machine/ts/machine/devices/audio/output.ts:346–352,403–425`; `machine/cpp/machine/devices/audio/output.cpp:261–267,322–348`. This supports a preservation/read hazard caution, not new out-of-range output guarantees, a padding contract or a runtime fix. AB06's earlier-end possibility remains true but alone is an incomplete newcomer caution.
