# Console overview: memory, storage and transfer facts

Facts-only editorial input, verified from live sources on 2026-10-18 at `ce3ef5b8f` (`master`). Initial unrelated changes: `.vscode/launch.json`, `.vscode/tasks.json`, untracked `docs/examples/`; preserved. No repository writes, builds, tests, runtime edits, architecture document or reference PDFs. Existing fact sheets supplied owner locations only; the claims below come from the named live leaves and owners. All sizes are bytes; KiB=1024 and MiB=1048576. Ranges use exclusive ends. Arithmetic endpoints/formulas are explicitly derived from source constants. The scope is guest u32 addresses and the two named installed-model products, not arbitrary host inputs or physical qualification.

## Reservation and firmware/program storage

| ID | Verified fact | Exact live sources |
|---|---|---|
| M08 | The declared I/O reservation is `[0x08000000,0x08040000)`, 256 KiB. The declared GEO scratch region is `[0x08040000,0x080c0000)`, 512 KiB. Their combined span before system statics is 768 KiB (`MIN_RAM_SIZE=0xc0000`); `DYNAMIC_RAM_BASE=0x080c0000`. These are declarations, not proof that every reserved byte is actively used by a device. | TS `machine/ts/spec/bmsx/memory_map.ts:25-33`; C++ `machine/cpp/spec/bmsx/memory_map.h:31-39`. |
| M09 | Implemented I/O aperture is smaller than the reservation. The mirrored IO index/count chain evaluates to `IO_SLOT_COUNT=16656=0x4110` words, hence `66624=0x10440` bytes: `[0x08000000,0x08010440)`. Memory sizes and intercepts slots using this count times four, not `IO_REGION_SIZE`. Reservation size and intercepted size are distinct, not contradictory. | TS producer chain `machine/ts/spec/bmsx/io.ts:3-160`, word/base `machine/ts/spec/bmsx/memory_map.ts:23,32`, consumer `machine/ts/machine/memory/memory.ts:145,162,836-845`. C++ producer chain `machine/cpp/spec/bmsx/io.h:15-173`, word/base `machine/cpp/spec/bmsx/memory_map.h:29,38`, consumer `machine/cpp/machine/memory/memory.cpp:95-97,725-727`, `machine/cpp/machine/memory/memory.h:134-140`. |
| M10 | System static DATA begins at `DYNAMIC_RAM_BASE=0x080c0000`; its BSS follows its emitted DATA bytes. The system linker exports cartridge static base as the end of system BSS. Cartridge DATA begins there and cartridge BSS follows cartridge DATA. Thus system DATA, system BSS, cartridge DATA, cartridge BSS occur in that order; their byte counts are image dependent. This is one shared toolchain producer, not a duplicated native linker. | Single producer `toolchain/ts/rompack/blua32_linker.ts:1064-1078,1099-1125,1128-1154`; mirrored base constants in M08. Mirrored descriptor identities: TS `machine/ts/spec/blua32/image_format.ts:21-25`; C++ `machine/cpp/spec/blua32/image_format.h:27-31`. |
| M11 | Static-storage construction checks the supplied RAM end (`RAM_BASE+ramByteCount`) and rejects excess; this is a build-time fit check, not a runtime allocator. In the installed 4 MiB model, `0x340000` bytes = 3.25 MiB remain after the 768 KiB pre-static span but BEFORE subtracting firmware and cartridge DATA/BSS. It is not a usable-heap/free-memory claim. | Producer `toolchain/ts/rompack/blua32_linker.ts:285-289,1107-1113,1136-1142`; arithmetic from M03/M08. |
| M12 | The linked image contains RODATA and DATA initializer payloads. It distinguishes DATA load address from DATA RAM run address and BSS RAM address; descriptor fields are not extra mapped memory. The exact firmware image size, static footprint and cartridge statics base are not fixed by the 16 MiB ROM window. | Producer `toolchain/ts/rompack/blua32_linker.ts:712-737,840-852,874-882`; mirrored descriptor offsets TS `machine/ts/spec/blua32/image_format.ts:19-27`, C++ `machine/cpp/spec/blua32/image_format.h:25-33`. |

## CPU-visible routes

| ID | Verified fact | Exact live sources |
|---|---|---|
| M13 | Ordinary CPU LOAD_MEM/STORE_MEM handlers derive a u32 byte address, apply the access-kind alignment mask, then use mapped Memory access. Word operations reach `readMappedWord`/`writeMappedWord`. This establishes the CPU-to-map route, not instruction-fetch timing or a C ABI. | TS `machine/ts/machine/cpu/cpu.ts:3080-3095,3117-3133`; C++ `machine/cpp/machine/cpu/cpu_dispatch.inl:621-633,646-658`. |
| M14 | Mapped word reads first route aligned live I/O addresses to the registered device handler or retained register slot; other addresses route to supplied system-ROM bytes, installed RAM backing or the cartridge controller. The cartridge controller then routes to the selected card. No CPU-linear VRAM range is added by this routing owner. | TS Memory `machine/ts/machine/memory/memory.ts:366-369,544-570`, card route `machine/ts/machine/devices/cartridge/controller.ts:80-85,163-165`; C++ Memory `machine/cpp/machine/memory/memory.cpp:245-251,434-460`, card route `machine/cpp/machine/devices/cartridge/controller.h:29-34,52-54`. |
| M15 | Main-window bytes beyond installed RAM backing do not become additional RAM or mirror lower RAM. Mapped accesses check the actual backing extent. The gap `[0x01000000,0x08000000)` and addresses at/above `0x31000000` are not mapped by these owners. | TS `machine/ts/machine/memory/memory.ts:349-363,544-570,627-656`; C++ `machine/cpp/machine/memory/memory.cpp:228-242,434-460,522-550`. |
| M16 | Within the system-ROM window, scalar read bytes beyond the supplied ROM image are zero-filled. System-ROM writes do not mutate firmware. Cartridge ROM/RAM accesses use card backing, not allocation equal to the declared window. | TS ROM `machine/ts/machine/memory/memory.ts:313-339,349-353,627-656`; card `machine/ts/machine/devices/cartridge/card.ts:147-188,191-218`. ## DMA transfer resources and cycle accounting

These are installed-model scheduler costs, not an independently specified external bus clock or measured sustained bandwidth.

| ID | Verified fact | Exact live sources |
|---|---|---|
| M17 | There are two DMA channels. Transfers operate on 32-bit/four-byte words. Programmed blocks are 1..16 words, clipped to remaining transfer count. Read/write address increments, when enabled, are four bytes. DMA routes each word through mapped memory. | TS spec `machine/ts/spec/bmsx/io.ts:10-11`, word size `machine/ts/spec/bmsx/memory_map.ts:23`; owner `machine/ts/machine/devices/dma/controller.ts:215-235,412-419`. C++ spec `machine/cpp/spec/bmsx/io.h:22-23`, word size `machine/cpp/spec/bmsx/memory_map.h:29`; owner `machine/cpp/machine/devices/dma/controller.cpp:145-165,336-343`. |
| M18 | The installed model's DMA costs are: RAM 1 cycle per word plus 1 setup cycle; system ROM 1 cycle per word; cartridge 8 cycles per word plus 4 setup cycles. Machine forwards these model fields into DMA timing in both implementations, so constructor-local defaults are not the installed values. | TS model `machine/ts/spec/bmsx/model.ts:8-12,46-52`; wiring `machine/ts/machine/machine.ts:98-105`; timing latch `machine/ts/machine/devices/dma/controller.ts:146-168`. C++ model `machine/cpp/spec/bmsx/model.h:13-17,51-57`; wiring `machine/cpp/machine/machine.cpp:41-48`; timing latch `machine/cpp/machine/devices/dma/controller.cpp:76-98`. |
| M19 | For a span of n words at region start: RAM cost `n+1`; system ROM `n`; cartridge `8n+4`; I/O/Other contributes zero region cost. The cartridge label applies to the whole mapped cartridge bus (ROM, RAM and MMIO), not only ROM despite timing-field names. | TS cost `machine/ts/machine/devices/dma/controller.ts:473-484`, classification `machine/ts/machine/memory/memory.ts:725-750`; C++ cost `machine/cpp/machine/devices/dma/controller.cpp:397-407`, classification `machine/cpp/machine/memory/memory.cpp:642-667`. |
| M20 | DMA combines source/destination costs per admitted span: if both are the same RAM region kind or both cartridge kind, sum read+write costs; otherwise use the greater cost. Setup is charged at a region start, not again for every subdivision caused by the other endpoint. Each admitted block starts its own region-start accounting. Total block cost has a minimum of 1 cycle. A single-region RAM-to-RAM block therefore costs `2n+2`; cartridge-to-RAM `max(8n+4,n+1)=8n+4`; RAM-to-I/O `n+1`; system-ROM-to-I/O `n`. These formulas concern admitted scheduled blocks, not end-to-end transfer throughput. | TS `machine/ts/machine/devices/dma/controller.ts:412-470`; C++ `machine/cpp/machine/devices/dma/controller.cpp:336-394`; coefficients M18/M19. |
| M21 | DMA schedules a service deadline at anchor cycle plus admitted block cost; service performs the mapped word reads/writes and advances raw addresses/count. The controller allows one admitted transfer block at a time; both channels can be BUSY with outstanding transfers. It chooses subsequent ready channels round-robin at block boundaries. | TS `machine/ts/machine/devices/dma/controller.ts:215-253,386-408,463-470`; C++ `machine/cpp/machine/devices/dma/controller.cpp:145-183,310-330,387-394`. |

## Precise remaining scope / withheld claims

1. No fixed firmware image byte length, fixed firmware DATA/BSS byte count, fixed cartridge static base or cartridge program capacity is established. Those require a specified linked system/cartridge image and its producer inputs, not window constants or boot-screen text.
2. GEO scratch is a named 512 KiB reservation in the map; no active 512 KiB datapath/scratch allocation or lifetime was proved. A search of the scoped geometry owners, BIOS and toolchain found no direct `GEO_SCRATCH_BASE/SIZE` use. Do not equate declaration with a proven populated buffer.
3. No top-of-RAM stack, byte-RAM guest heap address, fixed free-RAM amount or shared code/data pool is inferred. This slice did not audit thread/value-slot/LuaHeap storage owners, startup copy/zero execution, allocator semantics or boot/execution-domain transitions.
4. No single fixed cartridge ROM/RAM backing size or battery-backed persistence is inferred. Card media/configuration, packaging and persistence policy need their own bounded audit for any such claim. The two-card selection route is established; socket electrical details are not.
5. No CPU scalar load/store wait-state model, instruction fetch bus cost, physical arbitration waveform, electrical bus width, independent bus clock, or sustained MB/s rating is established. DMA timing constants are not interchangeable with CPU memory latency.
6. Model CPU frequency exists separately (`machine/ts/spec/bmsx/model.ts:7,47`; `machine/cpp/spec/bmsx/model.h:12,52`), but this sheet does not derive independent device/bus clocks from it. Graphics VRAM capacity/allocation, display apertures and image-decoder/audio routes belong to the other overview slices.
7. The intercepted-I/O-versus-reservation difference is real in both mirrors and intentionally kept distinct. No owner/spec or TS/C++ contradiction was found in the finite claims above. No claim of whole-runtime parity or behavior under arbitrary host-sized/non-u32 inputs is made.

## Independent mapper-span correction — 2026-10-18

The earlier M20 phrase “single-region” is not a universal single-enum-kind
rule. Cartridge classification returns separate spans at ROM/RAM/MMIO window
boundaries even while the returned kind stays Cartridge: TS
`machine/ts/machine/memory/memory.ts:747-750`, native
`machine/cpp/machine/memory/memory.cpp:664-667`. DMA starts setup accounting
again for each new span of that endpoint, but not a subdivision caused solely
by the other endpoint: TS `machine/ts/machine/devices/dma/controller.ts:412-470`,
native `machine/cpp/machine/devices/dma/controller.cpp:336-394`. The public
formula examples are therefore limited to one uninterrupted classified span
at each endpoint, excluding these boundary crossings. No runtime change.

## Public-reader terminology correction

“One active channel” was replaced in public prose by one admitted transfer block,
while both channel transfers can be BUSY. START checks only its own channel BUSY;
arbitration returns while any block is admitted and later selects ready channels.
Direct paired sources: TS `machine/ts/machine/devices/dma/controller.ts:131-144,386-408`;
C++ `machine/cpp/machine/devices/dma/controller.cpp:65-78,310-332`.
