## Raw facts

**PV01 — Register representation.** Spec defines 22 configuration words (indices 0..21), of which 12 are composition words (0..11); CSR/IMR occupy later indices. TS owns separate `Uint32Array(22)` programmed `registerWords` and retained `presentWords`; C++ owns separate `std::array<u32,22>` arrays. This is two configuration banks, not two pixel/surface banks.
- Spec pair: `machine/ts/spec/gx/pcrtc.ts:9-37`; `machine/cpp/spec/gx/pcrtc.h:10-38`.
- Owner pair: `machine/ts/machine/devices/gx/gpu_pcrtc.ts:539-558`; `machine/cpp/machine/devices/gx/gpu_pcrtc.h:181-202`.

**PV02 — Programmed vs retained lifetime.** Configuration MMIO reads return programmed words. A changed config write stores a raw word and marks presentation dirty; it does not overwrite the retained presentation bank. No-op same-word writes do neither. Beam-timing words update live `timing` and restart the beam immediately; presentation timing is separately dirty. The beam-timing classification is SMODE1 low/high and SYNCH1 low through SYNCV high; SMODE2 is not in that classification.
- Read/write pair: `machine/ts/machine/devices/gx/gpu_pcrtc.ts:580-599`; `machine/cpp/machine/devices/gx/gpu_pcrtc.cpp:325-343`.
- Classification pair: `machine/ts/machine/devices/gx/gpu_pcrtc.ts:223-227`; `machine/cpp/machine/devices/gx/gpu_pcrtc.cpp:58-62`.

**PV03 — Ordinary presentation latch copies configuration only.** If dirty, `latchPresentationWords` copies all 22 programmed words into retained words, optionally rebuilds retained presentation timing, clears both dirty flags, and publishes decoded `scanout` from the retained words/timing. No VRAM/pixel array participates in this function or publication. If not dirty, the latch returns without a copy/redecode.
- Latch pair: `machine/ts/machine/devices/gx/gpu_pcrtc.ts:723-730`; `machine/cpp/machine/devices/gx/gpu_pcrtc.cpp:446-453`.
- Publication pair: `machine/ts/machine/devices/gx/gpu_pcrtc.ts:825-827`; `machine/cpp/machine/devices/gx/gpu_pcrtc.cpp:548-550`.

**PV04 — Exact VBlank begin latch/order vs VBlank IRQ.** Runtime dispatches the PCRTC VBLANK_BEGIN edge into `enterVblank`. It increments VBlank sequence, calls GPU `presentReadyFrameOnVblankEdge`, advances input's VBlank edge, then raises **IRQ_VBLANK**, then enqueues tick completion if a frame is active. GPU's called method synchronizes command timing, latches PCRTC configuration, latches the other display registers, and seals the command prefix in that order. Therefore this path has completed the configuration latch before raising IRQ_VBLANK; it has not itself rasterized/copied the selected surface.
- Runtime pair: `machine/ts/machine/runtime/vblank.ts:44-64`; `machine/cpp/machine/runtime/vblank.cpp:31-48`.
- GPU pair: `machine/ts/machine/devices/gx/gpu.ts:1493-1514`; `machine/cpp/machine/devices/gx/gpu.cpp:975-996`.

**PV05 — IRQ_GX_PCRTC is different; VSINT is not the presentation-latch call.** `GxGpu.onService` calls PCRTC service and may raise IRQ_GX_PCRTC before returning its runtime-edge value. The CPU-executor timer handler consumes that returned edge afterward. PCRTC service computes VBlank-begin at activeDisplayHalfLines, separately computes VSYNC at vsyncHalfLine, updates FIELD/scanout traversal and VSINT on VSYNC, and only then returns a VBlank runtime edge if crossed. Do not substitute VSINT/IRQ_GX_PCRTC for PV04's IRQ_VBLANK ordering.
- Service pair: `machine/ts/machine/devices/gx/gpu.ts:1313-1330`; `machine/cpp/machine/devices/gx/gpu.cpp:665-681`.
- Dispatch pair: `machine/ts/machine/runtime/cpu_executor.ts:327-337`; `machine/cpp/machine/runtime/cpu_executor.cpp:313-323`.
- PCRTC pair: `machine/ts/machine/devices/gx/gpu_pcrtc.ts:666-676,692-719`; `machine/cpp/machine/devices/gx/gpu_pcrtc.cpp:389-399,415-442`.

**PV06 — Sealed prefix is executed work, not all queued work.** With no readback in progress, sealing sets `presentCommandCount = executedCommandCount`; with readback non-idle it uses the readback fence command count. This is a command-prefix boundary, not a pixel/surface-release token.
- Pair: `machine/ts/machine/devices/gx/gpu_command_buffer.ts:384-390`; `machine/cpp/machine/devices/gx/gpu_command_buffer.h:368-374`.

**PV07 — FBP/FBW/PSM and source offsets are decoded from retained words.** Each circuit uses enable bit PMODE[index]; `baseWord=(DISPFB.low & 0x1ff)<<12`; `framebufferWidth=((low>>9)&0x3f)*64`; `PSM=(low>>15)&0x1f`; source X=`high&0x7ff`, source Y=`(high>>11)&0x7ff`. PSMGX16=31; its local-memory address is `(baseWord + y*framebufferWidth + x) & (1024*1024-1)`. Both circuits consequently describe locations in the common local-memory address space, not copied circuit-private pixel stores.
- Decode pair: `machine/ts/machine/devices/gx/gpu_pcrtc.ts:361-378`; `machine/cpp/machine/devices/gx/gpu_pcrtc.cpp:120-139`.
- GX16/address pair: `machine/ts/machine/devices/gx/gpu_local_memory.ts:3-10,83-90`; `machine/cpp/machine/devices/gx/gpu_local_memory.h:7-15,78-80`.
- Address-space spec pair: `machine/ts/spec/gx/vram.ts:1-5`; `machine/cpp/spec/gx/vram.h:9-14`.

**PV08 — Raw publication is live references, not a display-image copy.** Device output's PCRTC word/timing/scanout fields refer to the retained owner objects; C++ spells them const references, TS installs owner arrays/objects in the output object once. Output separately exposes snapshot bytes and snapshot/replacement serials. Neither the output type nor its construction freezes a selected surface image when the PCRTC configuration latches.
- Definition pair: `machine/ts/machine/devices/gx/device_output.ts:4-19`; `machine/cpp/machine/devices/gx/device_output.h:13-42`.

**PV09 — Narrow actual consumer: paired software path.** `renderGxGpuSoftwareFrame` executes commands through `presentCommandCount` against software VRAM and then invokes scanout using the published retained scanout. The consumer's pixel helpers read the same retained software VRAM by the circuit's base/pitch/addressing; they do not read a PCRTC-owned surface snapshot. Backend state has one `Uint16Array`/`vector<u16>` VRAM. This establishes an actual data-consumer boundary, not physical per-pixel bus-fetch timing. Root independently inspected the other backend boundaries in `/tmp/bmsx-memory-shared-vram-boundary-facts.md` (not authority for this sheet's paired-source statements).

**PV10 — Actual copies exist elsewhere; do not conflate them with PCRTC latch.** Software backend reloads VRAM from snapshot bytes when snapshot serial changes. Explicit snapshot capture executes through `executedCommandCount`, serializes VRAM words, and calls `commitRenderedVramSnapshotBytes`; that method copies bytes into GPU snapshot storage and retires the rendered prefix. Interlaced software scanout retains composed output pixels and copies those to the output. None of these are a surface copy performed by `latchPresentationWords`.
- Reload/capture pair: `machine/ts/render/backend/software/gx_gpu.ts:22-26,59-68`; `machine/cpp/render/backend/software/gx_gpu.cpp:34-38,117-134`.

**PV11 — CSR_RESET is an explicit immediate publication boundary; CSR_FLUSH is not.** CSR action bits are FLUSH bit8 and RESET bit9. GPU CSR write gives RESET priority: clear GP0 FIFO, reset GPU registers, reset PCRTC, flag timing publication, latch other presentation registers, mark PCRTC presentation pending. PCRTC reset sets both config banks to reset words, resets CSR/IMR, rebuilds live/presentation timing, field0 and beam, and publishes configuration immediately. FLUSH alone only calls `clearGp0Fifo` before rescheduling; it does not call the PCRTC presentation latch/reset. Neither CSR branch performs a VRAM snapshot replacement/clear. The clear-FIFO routine resets ingress/FIFO, flushes accepted image-load state, aborts queued readback/commands, can complete accepted pending work, then clears pending command/parser state; it is not a harmless display latch.
- Action spec pair: `machine/ts/spec/gx/pcrtc.ts:58-61`; `machine/cpp/spec/gx/pcrtc.h:59-62`.
- CSR path pair: `machine/ts/machine/devices/gx/gpu.ts:1409-1422`; `machine/cpp/machine/devices/gx/gpu.cpp:918-931`.
- PCRTC reset pair: `machine/ts/machine/devices/gx/gpu_pcrtc.ts:560-571`; `machine/cpp/machine/devices/gx/gpu_pcrtc.cpp:305-316`.
- FIFO behavior pair: `machine/ts/machine/devices/gx/gpu.ts:1609-1627`; `machine/cpp/machine/devices/gx/gpu.cpp:1087-1105`.

**PV12 — Other explicit lifetime boundaries exist.** State restoration reinstalls programmed and retained banks separately, rebuilds both timings, restores beam/FIELD, and publishes retained configuration. Context restoration reinstalls only the first 12 programmed/present composition words and publishes. Entering supervisor context resets composition words, maps user circuit1 retained state into supervisor circuit2, copies composition words to retained state, and publishes. Thus “only VBlank can ever change retained configuration” would be false; PV04 is the ordinary runtime path, not an exclusion of reset/restore/context operations.
- Restore pair: `machine/ts/machine/devices/gx/gpu_pcrtc.ts:748-776,786-796`; `machine/cpp/machine/devices/gx/gpu_pcrtc.cpp:471-498,510-519`.
- Supervisor pair: `machine/ts/machine/devices/gx/gpu_pcrtc.ts:799-812`; `machine/cpp/machine/devices/gx/gpu_pcrtc.cpp:522-535`.

## Derived cautions / controlled example (not additional hardware guarantees)

**PV13 — Exact proposed two-surface mapping, derived from PV07.** With `DISPFB1.high=0`, `DISPFB1.low=0x000fa000` selects GX16 PSM31, FBW16 => 1024 words/row, FBP0 => base0. `0x000fa040` preserves every field except FBP0x40 => base0x40000=262144 words, equivalent to `(x=0,y=256)` in that 1024-word-row layout. For source dimensions 256x192 and source offsets0, first-surface addressed rows are `[0,191]`, second `[256,447]`; maximum second address is `0x40000 + 191*1024 + 255 = 457983`, below the 1,048,576-word addressing period. These source regions are disjoint. This derivation establishes the selected storage addresses, not that a particular DISPLAY/magnification/timing program produces exactly that source footprint; the latter must be separately sourced/decoded.
- Basis paired sources: PV07, specifically `machine/ts/machine/devices/gx/gpu_pcrtc.ts:371-378` / `machine/cpp/machine/devices/gx/gpu_pcrtc.cpp:132-139`, plus `machine/ts/machine/devices/gx/gpu_local_memory.ts:83-90` / `machine/cpp/machine/devices/gx/gpu_local_memory.h:78-80`.

**PV14 — What the controlled switch/reuse sequence can establish.** Sole-writer, circuit1-only, fixed non-overlapping GX16 regions, unchanged pitch/format/offset/geometry, and no texture/readback/circuit2 readers are necessary stated example assumptions. Writing only the new DISPFB1.low stages a configuration change (PV02). A qualifying subsequent VBlank-begin path latches it before raising IRQ_VBLANK (PV03-04). With no later configuration changes, subsequent software render calls use the new region, and a GP0 command confined to the old region cannot modify the new region (PV07,PV09,PV13). This is a conditional selected-address/non-overlap proof, not a generic ownership-release guarantee. A return to the old region later displays its then-current contents, not a saved copy captured by the earlier FBP write (PV03,PV09).
- Paired basis: `machine/ts/machine/devices/gx/gpu_pcrtc.ts:587-598,723-730` / `machine/cpp/machine/devices/gx/gpu_pcrtc.cpp:332-342,446-453`; `machine/ts/machine/runtime/vblank.ts:54-64` / `machine/cpp/machine/runtime/vblank.cpp:39-48`; `machine/ts/render/backend/software/gx_gpu.ts:49-57` / `machine/cpp/render/backend/software/gx_gpu.cpp:70-88`; PV07/PV13 mapping pairs.

**PV15 — Gaps / forbidden inference.** PCRTC spec/owner/latch does not expose a surface-release token, per-surface read-use tracking, atomic prepare+flip transaction, or physical per-pixel memory-fetch completion. It does not by itself prove that an arbitrary VBlank wait observed an edge after the programming store (stale/pending IRQ handling is a separate IRQ/firmware proof), nor that arbitrary other readers stopped using the old region. It also does not by itself prove GP0 completion merely because config latched: seal selects executed prefix, not all queued work (PV06). Root's proposed mask/ACK/counter sequence requires separate IRQ/guest-interrupt evidence and cannot be certified from these PCRTC sources alone. Backend-specific submission/sampling/order is a separate narrow consumer boundary; no generic old-surface-overwrite deadline is derived here.
- Paired limits visible in interface/latch: `machine/ts/machine/devices/gx/device_output.ts:4-19` / `machine/cpp/machine/devices/gx/device_output.h:13-42`; `machine/ts/machine/devices/gx/gpu_pcrtc.ts:723-730` / `machine/cpp/machine/devices/gx/gpu_pcrtc.cpp:446-453`; command-prefix pair `machine/ts/machine/devices/gx/gpu_command_buffer.ts:384-390` / `machine/cpp/machine/devices/gx/gpu_command_buffer.h:368-374`.

**PV16 — RESET/FLUSH partial-upload prefix means assembly-consumed payload, not port-admitted FIFO words.** Both CSR action branches reach the shared `clearGp0Fifo` (PV11). That function resets DMA ingress and GP0 FIFO **before** `flushImageLoadToVram`. A payload word becomes part of `gp0ImageLoadCommandWordCount` only when assembly pops it from GP0 FIFO and `consumeImageLoadWord` appends it to command storage/increments the count. Flush emits an upload only if that count exceeds the three-word header; header-only state is discarded. Therefore words still waiting in FIFO/DMA ingress at the clear boundary are not in the emitted upload prefix, even though they were admitted at a port. Software consumes the emitted command's word count to bound actual uploaded pixels. Public wording should name “payload words already consumed into upload assembly” if that is the intended prefix, rather than unqualified “accepted payload words”. This is a documentation-precision finding, not a spec/owner mismatch or proposed runtime change.
- CSR/shared-clear pair: `machine/ts/machine/devices/gx/gpu.ts:1409-1420,1609-1614`; `machine/cpp/machine/devices/gx/gpu.cpp:918-929,1087-1092`.
- Admission vs assembly pair: `machine/ts/machine/devices/gx/gpu.ts:1062-1073,1153-1159`; `machine/cpp/machine/devices/gx/gpu.cpp:579-590,721-727`.
- Assembled-prefix/flush pair: `machine/ts/machine/devices/gx/gpu.ts:1652-1681`; `machine/cpp/machine/devices/gx/gpu.cpp:1130-1158`.
