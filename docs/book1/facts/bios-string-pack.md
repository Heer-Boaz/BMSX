## Installation, signatures, dependencies, representation

- PK01. `string.pack`, `string.packsize`, and `string.unpack` are installed from the pack module into the base String Table, after pattern/format installation and before that Table becomes the String index. Owner: `machine/bios/string.lua:1-2,4-20`; module exports `machine/bios/string/pack.lua:448-452`.
- PK02. Source signatures are `pack(format, ...)`, `packsize(format)`, and `unpack_string(format, source, start_arg)`; public descriptors are `string.pack(format, ...)`, `string.packsize(format)`, `string.unpack(format, s [, pos])`. Owners: `machine/bios/string/pack.lua:277,340,370`; `toolchain/ts/lua/builtin_descriptors.ts:100-102`.
- PK03. `pack` returns one result, `concat(out)`; `packsize` returns one Number offset; `unpack` appends the next one-based position to its result Table and returns its values with captured Table-unpack. One data result is appended for every integer/float/c/z/s token; controls, x and X append none. Empty/control-only unpack normally returns just its next position. Extra pack arguments are not counted or rejected: only data tokens advance `arg_index`. Owners: `machine/bios/string/pack.lua:277-337,340-367,370-446`.
- PK04. Pack captures base `byte`, `char`, `sub`, Table `concat`, Table `unpack`, and the two float closures once at module initialization; replacing those public Table fields later does not replace these captured values. It does not capture global `select` or `error`. Owners: `machine/bios/string/pack.lua:1-9,79,82,106,299,304,308,315,327`.
- PK05. Capturing concat/unpack does not freeze their transitive globals: concat calls current global `tostring` for non-nil singleton entries; Table-unpack calls current global `select` only on an empty selected range. Pack's own argument extraction always uses current global `select`, and errors use current global `error`. Owners: `machine/bios/table.lua:52-78,81-98`; pack callsites in PK04. A normal completed pack-unpack result Table includes its next-position entry, so normal unpack here is not an empty-range call to Table-unpack.
- PK06. String lengths and indexes are Unicode codepoints, not UTF-8 bytes. Byte returns one codepoint from the requested one-based position, scanning from the beginning; Char constructs one valid scalar per numeric argument. The pack output is a String of codepoints, not a mapped byte buffer. Numeric fields and padding create codepoints 0..255, but c/z/s copy source codepoints without constraining them to this range. Unpack reads codepoints as digits with no 0..255 check/mask. Owners: `machine/bios/string/pack.lua:87-143,268-273,292-334,399-443`; paired byte/char `machine/ts/machine/cpu/cpu.ts:4320-4368`, `machine/cpp/machine/cpu/cpu.cpp:2176-2223`; paired LEN in the first STOP.
- PK07. Source-derived representation examples: `pack('c1', char(256))` copies codepoint256 unchanged; `packsize('c1')` remains1. `unpack('B', char(256))` reads numeric256 (then next position2); signed `b` instead subtracts256 once and returns0. These are not raw octet storage semantics. Owners: `machine/bios/string/pack.lua:115-143,307-313,361-362,399-406,415-420`; char boundaries in PK06.

## Format grammar, widths, state, alignment

- PK08. Every call starts at format index1 with zero-based data offset0 (unpack uses its requested source offset instead), little-endian=true, maximum alignment8. Constants are fixed values, not host-dependent: default i/I4, l/L4, T4, s-prefix4, j/J8, n8, f4, d8. Owners: `machine/bios/string/pack.lua:11-25,277-283,340-345,370-378`.
- PK09. Parser ignores only codepoint32 and9..13 between tokens. Decimal size/alignment suffixes are consecutive ASCII digits0..9, accumulated as `value = value * 10 + digit`; no sign, decimal point, separators, or whitespace inside a suffix. No digit-count or general numeric upper bound is imposed by this reader. Owners: `machine/bios/string/pack.lua:34-58,178-185`.
- PK10. Endian controls consume no argument/data: `<` selects little, `>` selects big, `=` selects the fixed little-endian default. `!N` sets maximum alignment to the parsed positive decimal N; a missing suffix or N<=0 throws `string.pack alignment must be a positive integer.` There is no power-of-two restriction and no finite/maximum check in this branch. Owners: `machine/bios/string/pack.lua:186-201`.
- PK11. Signed integer tokens: b1, h2, l4, j8, i[N] default4. Unsigned: B1, H2, L4, J8, I[N] default4, T4. i/I explicit size must be1..8 or throws `string.pack invalid integer size.` Fixed and sized integers align to min(maximum alignment, width), EXCEPT T: its parser explicitly returns alignment4, not min(maximum alignment,4). Owners: `machine/bios/string/pack.lua:12-21,208-223`.
- PK12. Float tokens f4, d8, n8, each aligned to min(maximum alignment,width), each one argument/result. No width suffix is read for these tokens. Owners: `machine/bios/string/pack.lua:22,224-227,302-306,359-360,407-414`.
- PK13. `cN` requires decimal digits (missing -> `string.pack expected a size for c format.`); zero is accepted, and there is no parser maximum. It has fixed sizeN and no automatic alignment. `z` has variable size, no alignment or suffix. `s[N]` is length-prefixed, prefix default4 or explicit1..8, otherwise `string.pack invalid length size.`; prefix alignment is min(maximum alignment,prefix width). Owners: `machine/bios/string/pack.lua:228-246,307-334`.
- PK14. `x` is one padding unit. `X` consumes no argument or target field: it emits/skips padding to the alignment found by looking ahead. Lookahead skips endian/alignment controls (tracking their future state locally), skips x and further X, then returns `c or b or a or 1` from the next data token, or1 at end. Thus X before integer uses its returned alignment, before float/s uses b, before cN uses N (not1), before z/end uses1. Later main-loop token parsing still processes all looked-ahead tokens normally. Owners: `machine/bios/string/pack.lua:202-207,250-266,295-296,355-356,393-398`; token return positions in PK11-PK13.
- PK15. Alignment padding formula is zero for align<=1; otherwise `(align - (offset % align)) % align`. It is relative to the call's current zero-based absolute source offset, including an unpack start position, not reset at each field or at the start of an unpacked subrecord. No implicit final/trailing record alignment occurs. Pack writes every padding codepoint as zero; unpack only bounds-checks/skips padding and never verifies its contents. Owners: `machine/bios/string/pack.lua:27-32,268-273,292-306,353-360,372,388-414`.
- PK16. Source-derived alignment examples: `packsize('!1bT')` is8, because T still aligns4; `packsize('bXc3')` is6, because Xc3 aligns offset1 to3 then c3 adds3; a trailing X adds no padding. Do not substitute stock Lua rules. Owners: PK11, PK14, PK15.
- PK17. Every other token throws `string.pack unsupported format option.` The same parser is called by all three interfaces; malformed formats can therefore use the string.pack-prefixed error text during packsize/unpack. There is no up-front validation pass: parsing and data work are interleaved, including lookahead parsing for X. Owners: `machine/bios/string/pack.lua:178-266,277-337,340-367,370-446`.

## Integer pack/unpack arithmetic and range

- PK18. Pack integer input is first `integer = value // 1`; if `integer ~= value`, it throws `string.pack integer value must be an integer.` Next it rejects above9007199254740991 or below-9007199254740991 with `string.pack integer value exceeds safe integer range.` It then applies width range [-256^size/2, 256^size/2-1] signed or [0,256^size-1] unsigned, rejecting outside it with `string.pack integer value out of range.` Owners: `machine/bios/string/pack.lua:11,60-85,102-113`.
- PK19. The integer path does not parse numeric Strings or coerce Boolean/Table/nil. Such values produce NaN for the arithmetic and fail the `integer ~= value` test. Numeric NaN fails the same test; positive/negative infinity reach the safe-integer-range error. Fractional Numbers fail the integer test, rather than being accepted after floor. Missing pack data arguments yield nil through current select and normally fail similarly. Owners: pack18; paired nonnumber arithmetic/Number accessor `machine/ts/machine/cpu/value_slots.ts:128-131`, `machine/ts/machine/cpu/cpu.ts:2551-2588,3589-3597`, `machine/cpp/machine/cpu/value.h:125-148`, `machine/cpp/machine/cpu/cpu_dispatch.inl:171-218`; paired floor `machine/ts/spec/blua32/numeric.ts:1-5`, `machine/cpp/spec/blua32/numeric.h:7-11`; select `machine/ts/machine/cpu/cpu.ts:4286-4318`, `machine/cpp/machine/cpu/cpu.cpp:2152-2174`.
- PK20. To encode a negative integer, add256^size once, then emit exactly size digits in selected endian order, using `%256` and repeated `//256` (big-endian uses descending powers256). Arithmetic remains the ordinary Number datapath; this is not a separate exact64-bit integer representation. This is important for size7/8: the post-add positive representation can exceed the safe exact integer interval even though the accepted original integer did not. Owners: `machine/bios/string/pack.lua:60-66,87-113`; numeric leaves in PK19.
- PK21. Read unsigned accumulates codepoint*multiplier, multiplier*=256, in selected endian order. It rejects accumulated value>9007199254740991 with `string.unpack integer exceeds safe integer range.` No lower-bound or digit<=255 validation occurs. Signed read happens only AFTER that check: if value>=256^size/2, subtract256^size once. Owners: `machine/bios/string/pack.lua:115-143`.
- PK22. Therefore a blanket signed7/8 two's-complement round-trip guarantee is unsupported: any ordinary nonnegative-octet representation with the sign bit set at width7/8 has raw unsigned value>=2^55 /2^63 and is rejected before signed conversion. Source-derived example: eight codepoints255 with `j` reach the safe-integer error rather than yielding-1. Even packing `j,-1` uses `-1 + 2^64` in Number arithmetic, so do not silently promise exact integer-word wrapping. Owners: PK18-PK21. No execution check was performed here.

## Floating fields: exact producer/consumer, not a repaired standard

- PK23. Pack f calls encode_float(value,4) for one Number bits result and writes four digits. Pack d/n calls encode_float(value,8), receiving high then low; little endian writes low4 little then high4 little, big writes high4 big then low4 big. Unpack performs the inverse chunk reads and calls decode_float(high,low,width); f supplies low0. Owners: `machine/bios/string/pack.lua:146-176`.
- PK24. Encode uses f32 exponent8/mantissa23 or f64 exponent11/mantissa52; sign starts0, sets1 only when value<0 and then negates value. Bias=2^(exponent_bits-1)-1; mantissa scale=2^mantissa_bits. NaN (`value ~= value`) sets all-ones exponent and mantissa1. Infinity sets all-ones exponent and zero mantissa. Zero leaves exponent/mantissa0; negative zero is not detected by value<0. Owners: `machine/bios/string/float/encode.lua:2-28`.
- PK25. Finite nonzero encode repeatedly divides values>=2 by2 / increments exponent, then multiplies values<1 by2 / decrements exponent; adds exponent bias. If exponent<=0, exact source expression is `mantissa = ((value / (2 ^ (1 - exponent - exponent_bias))) * mantissa_scale + 0.5) // 1`, exponent0. If exponent>=exponent_max, mantissa0/exponent_max. Otherwise mantissa=`((value - 1) * mantissa_scale + 0.5) // 1`; mantissa>=scale resets mantissa0 and increments exponent once. No further correction or range check follows that increment. Owners: `machine/bios/string/float/encode.lua:28-50`.
- PK26. f32 bits result is sign*2^31 + exponent*2^23 + mantissa. f64 outputs high=sign*2^31 + exponent*2^20 + (mantissa//2^32), low=mantissa%2^32. These exact equations, including the subnormal branch above, are the current source contract; do not replace them with a generic “IEEE754 native packing” statement. Owners: `machine/bios/string/float/encode.lua:52-55`.
- PK27. Float encode has no argument type validation. Under unchanged globals, a nonnumeric value such as nil or a numeric String is neither negative nor unequal to itself, differs from Number0, skips both Number-comparison normalization loops, and produces NaN arithmetic; digit writer feeds NaN to Char, whose numeric unsigned-word conversion makes codepoint0. Thus a source-derived nonnumeric f/d/n argument becomes four/eight zero codepoints, not the integer path's validation error. Numeric NaN instead takes the explicit exponent-all-ones/mantissa1 branch. Owners: encode24-26; `machine/bios/string/pack.lua:87-100,146-159`; paired arithmetic/equality/comparison `machine/ts/machine/cpu/cpu.ts:2551-2588,2659-2662,2692-2736`, `machine/cpp/machine/cpu/cpu_dispatch.inl:171-218,341-383`; paired Char `machine/ts/machine/cpu/cpu.ts:4353-4368`, `machine/cpp/machine/cpu/cpu.cpp:2209-2223`, unsigned conversion `machine/cpp/machine/cpu/value.h:199-222`. This consequence was not executed in this extraction.
- PK28. Decode sign=-1 if high>=2^31 else1; f32 exponent=(high//2^23)%2^8, mantissa=high%2^23. f64 exponent=(high//2^20)%2^11, mantissa=(high%2^20)*2^32+low. All-ones exponent + mantissa0 returns sign/0, other all-ones mantissas return0/0. Exponent0 returns sign*(mantissa/scale)*2^(1-bias); other values return sign*(1+mantissa/scale)*2^(exponent-bias). No additional source digit or encoding validation exists. Owners: `machine/bios/string/float/decode.lua:2-36` and pack23.

## Text field behavior

- PK29. Pack cN consumes one argument, copies exactly the first N codepoints by one-position sub calls, and pads with Char0 for positions>N's input length; input longer than N is truncated, not rejected. c0 still selects/consumes an argument but executes no input-length operation and emits no field data. Fixed fields are not automatically aligned. Owners: `machine/bios/string/pack.lua:228-234,307-313`.
- PK30. Pack z consumes one argument, scans positions1..#value; Byte==0 at any position throws `string.pack z strings must not contain zero bytes.` Nonzero codepoints are copied by Sub; a zero terminator is appended; tracked size is #value+1. No octet-range validation occurs. Pack s[N] consumes one argument, aligns its prefix, writes #value as unsigned integer of prefix width (therefore same integer-range errors), copies all codepoints unchanged, and tracks prefix width+#value; embedded zero codepoints are permitted. Owners: `machine/bios/string/pack.lua:314-334`.
- PK31. Unpack cN returns captured Sub(source,offset+1,offset+N), preserves all included codepoints/NULs, then advances by N. c0 returns empty String on an ordinary String input. Unpack z scans for the first zero codepoint within #source, returns the codepoints before it, and advances past the terminator; absence before end throws `string.unpack zero-terminated string not found.` Unpack s[N] reads unsigned prefix length, checks enough remaining codepoints, returns exactly that Sub span and advances by prefix+length; embedded zeros are preserved. Owners: `machine/bios/string/pack.lua:415-443`; base Sub `machine/bios/string/base.lua:58-82`.
- PK32. Neither format nor text/source arguments receive a common up-front String-type check. LEN accepts Strings/Tables and faults on unsupported categories. A Table used as format with length0 bypasses Byte/token work; one with positive length reaches Byte and fails its String requirement. Pack c0 can ignore even a non-length-bearing data argument. Pack cN/z/s can inspect Table length before any String requirement; cN can pad an empty Table, s can encode its zero length, z can terminate it. Nonempty Table sub calls can return the original Table when the requested span is exactly its full span; later concat then calls current tostring on it. Unpack control/x/X fields and c full-span branches likewise can accept a Table source without byte access. Those accepted branches retain the common Table-length STOP; do not describe every non-String as rejected. Owners: pack29-31; parser `machine/bios/string/pack.lua:178-185`; Sub `machine/bios/string/base.lua:58-82`; Table concat `machine/bios/table.lua:52-78`; paired LEN/Byte in PK06.

## Packsize, unpack start/bounds/results, errors and work

- PK33. Packsize walks the same tokens/state; adds one for x, adds alignment padding for X, padding+width for int/float, N for cN. On z or s it immediately throws `string.packsize format is variable-length.` It does not require or inspect field arguments and never appends automatic trailing padding. Owner: `machine/bios/string/pack.lua:340-367`.
- PK34. Unpack start is nil->1, otherwise floor-division by1, then offset=start-1. Offset<0 or offset>#source throws `string.unpack start index out of range.` Negative positions are NOT relative to end. Ordinary valid positions are1..#source+1; the latter can complete an empty/control-only/zero-width format but not consume data. The final result is offset+1, i.e. next one-based codepoint position, not consumed length. Alignment is still absolute offset based. Owners: `machine/bios/string/pack.lua:370-383`; padding in PK15.
- PK35. Start has no Number-tag/integer check: fractional finite Numbers floor; nonnumeric values/NaN become NaN via //, evade the `<0`/`>#source` checks, and are not repaired. Source-derived example: an empty format with an ordinary String source and a numeric String position returns NaN as its only next-position result. Positive/negative infinity hit the explicit out-of-range checks. Owners: pack34; paired arithmetic/comparison leaves PK19/PK27. This was not an executed probe.
- PK36. For x, X, integer, float, cN, prefix-width and prefixed-payload spans, unpack checks `offset + required_span > #source` before the applicable read/skip and throws `string.unpack string is too short.` z instead has its dedicated terminator error. Successful unpack does not require consuming all source codepoints; trailing data is allowed. Padding is not required to contain zero. There is no rollback around work performed for earlier fields if a later token errors. Owners: `machine/bios/string/pack.lua:388-443`.
- PK37. Public errors thrown directly by this module, exact capitalization/punctuation: `string.pack integer value must be an integer.`; `string.pack integer value exceeds safe integer range.`; `string.pack integer value out of range.`; `string.unpack integer exceeds safe integer range.`; `string.pack alignment must be a positive integer.`; `string.pack invalid integer size.`; `string.pack expected a size for c format.`; `string.pack invalid length size.`; `string.pack unsupported format option.`; `string.pack z strings must not contain zero bytes.`; `string.packsize format is variable-length.`; `string.unpack start index out of range.`; `string.unpack string is too short.`; `string.unpack zero-terminated string not found.` Locations respectively: `machine/bios/string/pack.lua:79,82,106,130,198,219,231,242,247,319,364,374,390-440,427`. Shared Byte/Char and unsupported-LEN faults remain their existing owners, not newly branded pack errors.
- PK38. All three interfaces are ordinary BIOS closures, not MMIO banks: no per-interface register addresses, reset values, IRQ sources, latched device state, or dedicated save-state words appear in these inspected modules. They parse by repeated String Byte/Sub calls, allocate output/temporary Tables and Strings, and pack-unpack joins/expands result collections. Byte scans from the start for each indexed access; integer/float operations add their digit loops, float normalization loops and Table recursion. No fixed whole-call cycle rate is declared. Owners: full `machine/bios/string/pack.lua:1-452`; immediate Byte in PK06; concat/unpack PK05; float loops PK25.
- PK39. Incremental Byte/Char builtin surcharge is2 each (argument/result coefficients0), not full wrapper call cost or a physical transfer rate. Paired owners: `machine/ts/machine/cpu/value.ts:109-110,121-122`; `machine/cpp/machine/cpu/value.h:63-72`. This extraction does not measure total cycles or attach a safe bound to very large cN/!N suffixes or expanded outputs.
