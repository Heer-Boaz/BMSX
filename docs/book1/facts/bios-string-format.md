## Entry, representation and dependencies

- F01. Installed export is `string.format`; compositor obtains `require('string/format')`, assigns its `format` member to the shared String table and installs that table for String indexing. The format module returns a Table containing only `format = format`. Sources: `machine/bios/string.lua:12-20`; `machine/bios/string/format.lua:461-463`.
- F02. Authoring descriptor is exactly `string.format(format, ...)`, parameters `['format','...']`. It supplies no supported-specifier list, argument type checks, output-capacity rule or timing. Actual implementation is an ordinary function `(format, ...)`, initializes argument_index1/outputempty/index1, caches its initial `#format` for the main scan and returns exactly `output` if it completes. Sources: `toolchain/ts/lua/builtin_descriptors.ts:99`; `machine/bios/string/format.lua:282-287,458-459`.
- F03. At module initialization it captures base-String byte, char, sub and rep; Table concat; Math modf. Later changes to those exposed table fields do not replace these local references. `select`, `tostring` and `error` are not captured here and are looked up where called. Sources: `machine/bios/string/format.lua:1-9,155-157,184,200-202,259,294,326,351,379-381,447-452`.
- F04. Capturing concat/sub does not freeze their mutable transitive dependencies: Table concat invokes current global tostring; base sub calls its own captured byte/char/concat. Installed default tostring is `return '' .. value`. Sources: `machine/bios/table.lua:52-77`; `machine/bios/string/base.lua:1-4,58-82`; `machine/bios/base.lua:235-237`.
- F05. ## Grammar and argument consumption

- F08. Non-percent source codepoints are copied with char into output in order. A terminal bare percent raises `string.format incomplete format specifier.`. Immediate `%%` appends one percent, skips two source positions and consumes no argument; it bypasses flags/width/precision/modifiers. Source: `machine/bios/string/format.lua:287-299`.
- F09. Non-escape conversion grammar, in actual order: zero or more recognized flags, optional width, optional dot plus precision, zero or more ignored modifiers, then one conversion codepoint. There is no positional `$` argument syntax in these branches. Source: `machine/bios/string/format.lua:300-376`.
- F10. Flags are `-`(45), `+`(43), space(32), `0`(48), `#`(35). Their order and repetition are unrestricted; each sets a Boolean. Parsing stops at first unrecognized codepoint. Source: `machine/bios/string/format.lua:300-322`.
- F11. Width is either `*`, which consumes the next vararg, or a run of ASCII decimal digits only. Digit accumulation is `value = value*10 + (code-48)` with no digit-count/maximum-width check. Leading zeros have already been consumed as flags. Width absent leaves nil. Sources: `machine/bios/string/format.lua:21-27,57-70,324-342`.
- F12. A star width uses only first result of captured modf(value); for finite Numbers it truncates toward0. Negative result sets left alignment and width to its negation, otherwise width equals result. It increments argument_index before conversion-value selection. No dedicated width type/range validator is present. Sources: `machine/bios/string/format.lua:325-335`; `machine/bios/math.lua:27-32,59-62`.
- F13. A dot introduces precision. Dot at end raises incomplete-specifier error. Precision `*` consumes another vararg, takes modf first result and records it only when >=0; negative or NaN precision is treated as absent. Otherwise a run of ASCII decimal digits is accumulated, with no digits meaning precision0. Sources: `machine/bios/string/format.lua:344-363`; `machine/bios/math.lua:27-32,59-62`.
- F14. Any number/order/repetition of `l`, `L`, `h` codepoints is skipped after width/precision. They do not select a wider/narrower representation. Ending in these modifiers raises incomplete-specifier error. Source: `machine/bios/string/format.lua:365-374`.
- F15. Supported conversions exactly: `s`, `c`, `d`, `i`, `u`, `o`, `x`, `X`, `f`, `F`, `e`, `E`, `g`, `G`, `q`. A recognized conversion consumes one next vararg after any stars. All other conversion codepoints call the unsupported-specifier error path; `a`, `A`, `p`, `n`, `%` with parsed flags/width, and `$` have no special branch. Source: `machine/bios/string/format.lua:376-453`.
- F16. Each select call uses the current argument_index followed by all varargs, assigned to one local, and increments the index. Extra varargs never reached by conversion/star parsing are ignored. There is no format-wide argc preflight or too-many-arguments error. Sources: `machine/bios/string/format.lua:283,326-328,351-353,379-381,387-389,392-395,431-432,447-449`. Default select returns suffix values at a positive index and no result after the end; exact scalar nil-adjustment/omitted-parameter mechanics belong to the existing CPU call contract rather than a formatter-specific validator. Sources for select suffix behavior: `machine/ts/machine/cpu/cpu.ts:4286-4318`; `machine/cpp/machine/cpu/cpu.cpp:2152-2174`.

## Common padding and signs

- F17. Padding compares width to sum of codepoint lengths of sign+prefix+content. If width absent or no greater than total, concatenate sign,prefix,content unchanged: width never truncates. Source: `machine/bios/string/format.lua:80-93`.
- F18. If padding needed, left alignment appends spaces and wins over zero_pad; otherwise zero_pad inserts zeros after sign and prefix but before content; otherwise spaces precede sign+prefix+content. Sources: `machine/bios/string/format.lua:80-93`.
- F19. Sign selection is negative test first (`value<0` gives `-`), else plus gives `+`, else space gives one space, else empty. Plus wins over space; there is no separate sign-bit test for negative zero. Sources: `machine/bios/string/format.lua:95-106,398-400,435`.
- F20. s/c/q force zero-padding false; their plus/space/# flags have no conversion effect. Signed d/i use plus/space; unsigned u/o/x/X do not. Integer width-zero-padding is disabled whenever precision is present, including precision0. Float branches pass zero_pad even with precision. Sources: `machine/bios/string/format.lua:378-445,446-450`.

## String, codepoint and quoted conversions

- F21. `%s` first uses current global tostring(value), then if precision present applies captured sub(text,1,precision), then normal space/left padding. Precision0 returns empty for normal converted Strings; precision counts codepoints. No String-only input check precedes tostring. Source: `machine/bios/string/format.lua:378-385`; slice branch `machine/bios/string/base.lua:58-81`.
- F22. `%c` uses the exact call `char((modf(value)))` and then normal space/left padding. Do not impose stock-Lua first-result grouping: installed call delivery is covered by the compiled-call correction card below. Precision is parsed/consumes a star but ignored by conversion. Source: `machine/bios/string/format.lua:386-390`.
- F23. Char's received Number is converted to U32 by truncation/wrapping; it rejects values>10FFFFH or D800H..DFFFH and accepts0 as NUL. NaN/infinities map to word0 at this boundary. It rejects a non-Number received directly, but formatter modf arithmetic is not such a direct char argument check. Sources: `machine/ts/machine/cpu/cpu.ts:4353-4367`; `machine/cpp/machine/cpu/cpu.cpp:2209-2222`; U32 owner `machine/cpp/machine/cpu/value.h:199-221`.
- F24. `%q` first uses current tostring(value), encloses output in double quote codepoints, and scans every resulting codepoint. It emits `\\n` for10, `\\r` for13, `\\t` for9, `\\\\` for92, `\\"` for34. Other codepoints<32 or=127 become backslash plus decimal code padded on left to3digits. Every other codepoint is copied through char. Source: `machine/bios/string/format.lua:258-280`.
- F25. `%q` parses but ignores precision, including a consumed star; it applies only normal width/left padding after quoting. It is not specified here as a round-trip serialization of arbitrary original values: all categories are first converted by tostring. Source: `machine/bios/string/format.lua:446-450,258-280`.

## Integer conversions

- F26. d/i take first modf result as the integer; finite Number fractions truncate toward0. Signed magnitude is negated only when integer<0. No 32-bit word restriction is imposed on d/i by this branch. Source: `machine/bios/string/format.lua:391-401`; trunc owner `machine/bios/math.lua:27-32,59-62`.
- F27. u/o/x/X take modf first result, bitwise AND with FFFFFFFFH, then if signed result<0 add100000000H. Thus their magnitude is U32; arithmetic bitwise result is a signed32 Number before the adjustment. Sources: `machine/bios/string/format.lua:108-114,394-401`; paired BAND `machine/ts/machine/cpu/cpu.ts:2551-2592`; `machine/cpp/machine/cpu/cpu_dispatch.inl:222-229`; word conversion `machine/cpp/machine/cpu/value.h:199-229`.
- F28. d/i/u use base10; o base8; x/X base16. Value0 initially emits one `0`. Otherwise the loop prepends digit(value%base) while value>0 and replaces value with value//base; digits>=10 use a..f or A..F for X. Sources: `machine/bios/string/format.lua:116-137,402-408`.
- F29. Present integer precision left-pads digits with zeros to at least that count. Precision0 and magnitude0 clears digits. Alternate octal subsequently restores a single0 if digits empty, or prepends0 if first digit is not0. Source: `machine/bios/string/format.lua:409-427`.
- F30. Alternate x/X adds prefix0x/0X only for nonzero magnitude; alternate d/i/u adds no prefix. Sign/prefix placement then follows common padding, with zero-width padding permitted only if precision absent. Source: `machine/bios/string/format.lua:417-429`.
- F31. Signed NaN magnitude is neither0 nor>0, so unsigned_to_base returns empty digits; flags/precision can still add sign/padding/zeros. Either signed infinity produces positive-infinite magnitude and enters repeated base division without a finite progress condition. Unsigned NaN and either infinity pass the U32 boundary to0 instead. These are source consequences, not execution measurements. Sources: `machine/bios/string/format.lua:108-137,391-429`; `machine/cpp/machine/cpu/value.h:199-229`; paired arithmetic dispatch `machine/ts/machine/cpu/cpu.ts:2551-2604`; `machine/cpp/machine/cpu/cpu_dispatch.inl:171-229`.

## Floating conversions — exact implemented algorithms, not printf accuracy claims

- F32. f/F fixed; e/E scientific; g/G general. Uppercase forms recognize NAN/INF and uppercase exponent E. All receive raw selected value without a dedicated Number validator; finite_text checks value!=itself and equality against +/- (1/0). NaN gives nan/NAN, either infinity inf/INF, with sign applied separately. Source: `machine/bios/string/format.lua:139-148,430-445`.
- F33. For non-special values, sign is determined from original value and magnitude is value<0 ? -value : value. Default f/F/e/E precision6; explicit0 is retained. All float padding uses sign, no base prefix, width/left/zero flags. Source: `machine/bios/string/format.lua:38-43,95-106,430-445`.
- F34. pow10 starts1 and multiplies by10 while exponent>0, decrementing exponent1 each time. It is not a bounded precomputed table and has no precision cap. Source: `machine/bios/string/format.lua:29-36`.
- F35. Fixed algorithm: scale=pow10(precision); rounded=first modf(value*scale+0.5); whole=rounded//scale; fraction=rounded%scale; text=current tostring(whole). For precision>0 append dot plus current tostring(fraction), left-padded with0 to precision codepoints. Precision0 adds dot only when alternate. Source: `machine/bios/string/format.lua:150-162`.
- F36. Decimal normalization starts exponent0 and repeatedly divides value by10 while>=10, or multiplies by10 while0<value<1. It returns exponent and resulting mantissa. No precision/rounding-selected branch is involved at this stage. Source: `machine/bios/string/format.lua:164-175`.
- F37. Scientific0 uses fixed_digits(0,precision,alternate) plus exponent0 suffix. Otherwise normalize, set scale=pow10(precision), rounded=first modf(mantissa*scale+0.5); if rounded>=10*scale, divide rounded//10 and increment exponent. Build whole/fraction as fixed digits, then append suffix. Source: `machine/bios/string/format.lua:187-207`.
- F38. Exponent suffix is e/E plus explicit + or -, plus current tostring(abs(exponent)) left-padded with0 to at least2codepoints. This is a minimum width, not a two-digit limit. Source: `machine/bios/string/format.lua:177-185`.
- F39. General precision defaults6; explicit0 becomes1 significant digit. It calculates exponent from unrounded magnitude (0 uses exponent0). If exponent<-4 or exponent>=significant, use scientific with precision significant-1; else use fixed with precision significant-exponent-1. It does not redo this branch decision after rounding. Source: `machine/bios/string/format.lua:232-248`.
- F40. General without# calls strip_fraction_zeros: find first e/E and detach suffix; remove *all* trailing zero codepoints from remaining text, then remove a trailing dot; reattach suffix. This loop does not first require a decimal point, so it can remove integer trailing zeros as well. Example of exact algorithm reduction, not execution evidence: general precision3 with magnitude100 chooses fixed precision0 text `100`, then strips to `1`. Sources: `machine/bios/string/format.lua:209-229,232-250`; fixed construction `:150-162`.
- F41. General with# skips zero stripping. G then applies ASCII-only uppercasing to every remaining output codepoint, using captured byte/char and concat. Uppercase mapper allocates a temporary Table and appends at #out+1. Sources: `machine/bios/string/format.lua:45-55,249-255`.
- F42. This implementation's rounding is the displayed multiply/plus0.5/modf algorithm. No source contract here establishes correctly rounded printf, decimal digit accuracy for every finite Number, locale behavior, hexadecimal float support, a fixed maximum exponent/precision or large-precision completion/resource guarantee. Sources defining the actual bounded claim: `machine/bios/string/format.lua:29-36,150-207,232-255,430-445`.
