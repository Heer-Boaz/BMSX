# BMSX Table facts: keys, missing reads, deletion, mutation length

Baseline inspected: `5a5a26e15`. Read-only extraction; no owner edits and no tests run. `git status --short` initially showed only unrelated `.vscode/launch.json` / `.vscode/tasks.json` changes. These are source facts, not prose for a chapter, a conformance judgment, or a full GC/iteration/metamethod audit. Paths below are repo-relative. Paired agreement is stated only within the inspected boundary.

## 1. Representation and key categories

- **Runtime Table values and keys use guest value categories.** TS `machine/ts/machine/cpu/value.ts:8-18,44-50,52-70` provides Nil, False, True, Number, String, Table, Closure, BuiltinFunction, Thread, with scalar/reference columns used by Table. Native `machine/cpp/machine/cpu/value.h:29-40,95-145` provides a raw `uint64_t Value`, encoded nonnumeric tags, and untagged binary64 numbers. Table dispatch is `machine/ts/machine/cpu/table.ts:104-146`; native Table consumes Value directly at `machine/cpp/machine/cpu/table.cpp:393-443`. **Mirrored disposition: different physical representations, paired guest categories; do not classify native values by host shape.**

- **Nil is not an admissible lookup key here, including a lookup on an empty table.** General get/load throws `LUA_FAULT_REASON_INDEX_NIL` before searching; assignment, even assignment of nil, throws the same reason before deleting/searching. TS `machine/ts/machine/cpu/table.ts:149-158,748-757,790-800`; native `machine/cpp/machine/cpu/table.cpp:393-396,411-414`. **Mirrored: agrees.** This is separate from a missing *admissible* key returning nil.

- **Every other represented category can reach key storage; the Table mutation owner has no NaN rejection.** After the nil-key branch, TS `store` classifies an array key and otherwise finds/inserts a hash key: `machine/ts/machine/cpu/table.ts:790-852`. Native counterpart `machine/cpp/machine/cpu/table.cpp:411-443`. **Mirrored: agrees for represented nonnil keys, including boolean, number, string, table, closure, thread, builtin-function keys.** This is not an assertion that arbitrary host objects are guest values.

- **Only positive integral numeric keys 1 through 0x7fffffff are array-eligible.** TS `machine/ts/machine/cpu/table.ts:27,1415-1424`; native `machine/cpp/machine/cpu/table.cpp:42-47` -> `machine/cpp/machine/cpu/table.h:198-209`. Thus zero, negative numbers, fractions, NaN, infinities, and numbers above that bound are not array-eligible; they still follow the admitted numeric-key hash path. **Mirrored: agrees.** Native eligibility uses the `int` maximum; the declared table boundary here is `std::numeric_limits<int>::max()` rather than an independent hardcoded hexadecimal constant.

- **Array eligibility is not a key-type distinction.** An eligible key uses the existing array slot if in capacity, otherwise hash lookup/storage; rehash may redistribute entries without changing their key categories. TS read `machine/ts/machine/cpu/table.ts:159-180,748-757`, write `:801-852`, rehash `:1048-1097`, reinsertion `:1156-1181`; native read `machine/cpp/machine/cpu/table.cpp:397-408`, write `:415-443`, rehash `:154-193`, reinsertion `:213-227`. **Mirrored: same lookup/placement boundary; length side effects have the exception in section 4.** Avoid presenting array/hash placement as two guest table kinds.

## 2. Key equality, specifically not ordinary numeric equality

- **Tag/category distinctions are preserved; no string-number or boolean-number key coercion exists in this owner.** TS `machine/ts/machine/cpu/table.ts:906-930` rejects unequal tags before comparison. Native `machine/cpp/machine/cpu/table.cpp:73-74` delegates to `ValueEq`, `machine/cpp/machine/cpu/value.h:317-323`, which compares numeric values numerically only when both are numeric, otherwise raw encoded words. **Mirrored: agrees for guest-produced keys.** Numeric key `1`, string key `"1"`, and boolean key `true` are distinct categories.

- **+0 and -0 are the same table key.** They are not array-eligible. Numeric equality accepts them; numeric hashing explicitly normalizes either zero to positive zero. TS `machine/ts/machine/cpu/table.ts:879-887,916-918`; native `machine/cpp/machine/cpu/value.h:282-292,317-323`, via Table delegation `machine/cpp/machine/cpu/table.cpp:69-74`. **Mirrored: agrees.**

- **Canonical numeric NaN is a usable table key and repeated NaNs address the same key.** TS Table equality explicitly accepts two NaNs (`stored !== stored && scalar !== scalar`) and hashes NaN consistently: `machine/ts/machine/cpu/table.ts:881-887,916-918`. Native numeric construction canonicalizes NaN to one numeric word, `machine/cpp/machine/cpu/value.h:132-139`; `ValueEq` first accepts raw word equality, `:317-323`, and hashes the canonical numeric word at `:282-292`. TS numeric conversion also canonicalizes NaN, `machine/ts/machine/cpu/value.ts:48-50`, used by host-value Table set `machine/ts/machine/cpu/table.ts:132-134`. **Mirrored: agrees at the canonical guest-number boundary.** Do not infer missing-key behavior from `NaN == NaN` being false. Arbitrary noncanonical manually forged native words are not claimed.

- **Ordinary numeric EQ differs precisely on NaN.** TS EQ dispatch `machine/ts/machine/cpu/cpu.ts:2692-2699` calls `readRKEquals`; its numeric case uses `leftScalar === rightScalar`, `:3546-3578`. Native `machine/cpp/machine/cpu/cpu_dispatch.inl:341-349` uses decoded-double `==` for two numbers, not Table `ValueEq`. Consequently ordinary numeric NaN EQ is false while the canonical NaN table key matches itself. **Mirrored: agrees.**

- **String keys compare their StringId scalar, not host StringValue identity and not newly compared text at each Table access.** TS key conversion `machine/ts/machine/cpu/table.ts:113-114,135-137`, equality `:920-922`; native string construction `machine/cpp/machine/cpu/value.h:163-165` and equality `:317-323`. **Mirrored: agrees at StringId boundary.** Content interning/encoding policy is a producer fact outside this Table extraction; no text-normalization claim is made.

- **Reference-category keys preserve guest reference identity, not structural contents.** TS Table/Thread/Closure keys compare their stored reference, `machine/ts/machine/cpu/table.ts:923-926`, and hash by their reference's hashId `:897-900`. Native those tags carry pointer payloads, `machine/cpp/machine/cpu/value.h:167-176`, and raw encoded-word equality `:317-323`; their hash uses object hashId, `:274-275,305-308`. **Mirrored: same guest identity boundary; separate table/closure/thread objects are not structurally compared.**

- **Builtin-function keys use their canonical runtime identity.** TS compares builtin id `machine/ts/machine/cpu/table.ts:920-922`, with canonical descriptors indexed by id at `machine/ts/machine/cpu/value.ts:103-107,113-146`. Native descriptor-pointer payload `machine/cpp/machine/cpu/value.h:185-187`, raw encoded equality `:317-323`, and CPU producer picks `m_builtinFunctions[id]` at `machine/cpp/machine/cpu/cpu.cpp:404-406`. **Mirrored: agrees for CPU-produced builtin descriptors; no claim for invented host descriptors.**

## 3. Missing admissible keys and nil stores

- **A missing admissible key reads nil.** TS general `getByParts` returns null when no matching node, `machine/ts/machine/cpu/table.ts:748-757`; encoded load calls `target.setNil`, `:149-180`; integer and string leaves do likewise, `:183-214,276-294`. Native general `get`, integer get and string get return `valueNil()`, `machine/cpp/machine/cpu/table.cpp:393-408,446-455,486-492`. **Mirrored: agrees.** An allocated but empty array slot is also nil; presence of spare capacity does not make an entry.

- **Assigning nil removes the effective mapping, not a separately retrievable nil-valued entry.** In-capacity array writes store a Nil tag/value; out-of-array nil writes remove the hash node. General TS `machine/ts/machine/cpu/table.ts:801-824`, string-specific `:445-454`, removal's absent/dead no-op `:1322-1325`, actual removal `:1343-1387`; native general `machine/cpp/machine/cpu/table.cpp:415-430`, string-specific `:512-516`, absent/dead no-op `:319-322`, removal `:341-374`. **Mirrored: agrees on observable read result.** Effective deletion at an array-key position may change cached length as below.

- **Overwriting an existing nonnil hash mapping changes its value without invoking rehash or changing cached length in that return branch.** TS `machine/ts/machine/cpu/table.ts:826-833`; native `machine/cpp/machine/cpu/table.cpp:432-438`; integer native `:472-478`. **Mirrored: agrees.** This branch must not be described as unconditionally recomputing sequence length.

## 4. Cached length and exact mutation transitions; STOP on mirror difference

- **The Table constructor's capacities do not create live entries or establish length equal to capacity.** TS initializes `arrayLength = 0` and nil tags `machine/ts/machine/cpu/table.ts:52,68-84`; native `m_arrayLength = 0` `machine/cpp/machine/cpu/table.h:242-243` and nil-filled capacity `machine/cpp/machine/cpu/table.cpp:19-28`. CPU NEWT passes capacity operands, not populated values: TS `machine/ts/machine/cpu/cpu.ts:2543-2549` -> `:515-520`; native `machine/cpp/machine/cpu/cpu_dispatch.inl:165-168` -> `machine/cpp/machine/cpu/cpu.cpp:408-418`. **Mirrored: agrees.** Compiler decisions for source list literals are not established by these runtime allocation leaves.

- **Table LEN reads the mutation-maintained cached length directly.** TS `machine/ts/machine/cpu/cpu.ts:2672-2685` reads Table `arrayLength` at `:2680-2682`; native `machine/cpp/machine/cpu/cpu_dispatch.inl:319-330` calls Table `length`, whose entire owner is `machine/cpp/machine/cpu/table.cpp:547-549`. There is no search, metatable lookup, total-key count, or largest-key scan in those LEN leaves. **Mirrored: agrees on the read mechanism; not on every producer transition.**

- **Deletion transition is paired:** when a qualifying integer key `k` is assigned nil and `k-1 < L`, set `L = k-1`; keys at or after the current boundary do not shorten it further. TS general `machine/ts/machine/cpu/table.ts:801-824`, array-key helper `:255-273`; native array setters `machine/cpp/machine/cpu/table.h:172-195`, generic `machine/cpp/machine/cpu/table.cpp:425-430`, integer `:464-470`. **Mirrored: agrees for these branches.** Values above a newly opened hole remain mapped; deletion does not clear them.

- **TS nonnil insertion/refill transition:** in an existing array slot, if `k-1 == L`, scan from `L` until the first missing numeric `index+1`, including the hash portion when outside array capacity; if `k-1 != L`, that array branch leaves L unchanged. New hash insertion for array-eligible `k` invokes the same scan iff `k-1 == L`. Sources: `machine/ts/machine/cpu/table.ts:801-812,1188-1219,1426-1440`; integer fast store `:255-273` shares that scan. Scan reads the concrete Table only, not metatable inherited entries. **Native integer path agrees:** `machine/cpp/machine/cpu/table.h:186-195`; `machine/cpp/machine/cpu/table.cpp:49-67,458-483,255-269`. For a simple populated prefix within array capacity, filling its first hole advances over consecutive nonnil entries and stops at the next nil.

- **MISMATCH — STOP universal length/hole-refill claim.** Native generic numeric array writes use `setArraySlot`, which, upon a boundary refill, scans **only while `newLength < m_array.size()`**: `machine/cpp/machine/cpu/table.h:172-184`. It is called by generic `Table::set` at `machine/cpp/machine/cpu/table.cpp:415-421`, `rawSet` at `:255-262`, and native numeric fast setter at `machine/cpp/machine/cpu/table.h:36-43`. Native SETT actually reaches that numeric fast setter at `machine/cpp/machine/cpu/cpu_dispatch.inl:152-161`. TS equivalent general write always reaches the cross-hash scanner (`machine/ts/machine/cpu/table.ts:801-812,1426-1440`; SETT leaf `machine/ts/machine/cpu/cpu.ts:2502-2540` -> store leaf `:729-749`). Native SETI, in contrast, reaches `setIntegerArraySlot` and the cross-hash scanner (`machine/cpp/machine/cpu/cpu_dispatch.inl:94-101`; `machine/cpp/machine/cpu/table.h:53-59,186-195`). **Mirrored disposition: unresolved observable producer difference; do not publish that every insertion/refill makes `#t` equal the same maximal nonnil prefix in both runtimes.** No owner fix attempted. Extraction itself did not execute this path. Root subsequently reproduced the difference with an actual33-cycle SETT/LEN CPU program; see cpu-values-execution.md for both observed rows. No intended common result is inferred.

- **Rehash recomputes mutation length by replay, rather than copying its old numeric value.** TS reset/reinsert `machine/ts/machine/cpu/table.ts:1152-1181`; native `machine/cpp/machine/cpu/table.cpp:213-227`; both call rawSet for old live entries. **Mirrored: same replay mechanism, with native generic-array scan difference above.** Therefore do not promise that every non-sequence-key mutation is length-inert if it causes rehash while the cache is already path-dependent.

- **Clear resets length to zero.** TS `machine/ts/machine/cpu/table.ts:506-518`; native `machine/cpp/machine/cpu/table.cpp:551-558`. **Mirrored: agrees.** Snapshot restoration and GC-driven removals are deliberately not audited by this task.

## 5. Metatable boundary established by the inspected index/write leaves

- **A raw Table load does not itself traverse metatables.** TS load/get owner `machine/ts/machine/cpu/table.ts:149-180,748-757`; native `machine/cpp/machine/cpu/table.cpp:393-408`. CPU table read chooses raw load if no metatable and resolution otherwise: TS `machine/ts/machine/cpu/cpu.ts:619-653,655-685,687-727`; native `machine/cpp/machine/cpu/cpu.cpp:3243-3332`. **Mirrored: agrees.**

- **The implemented index-chain resolution reads a direct string-keyed metatable member and only follows it when that value is another Table.** TS `machine/ts/machine/cpu/table.ts:334-347`, resolution `:349-411,414-438`; native `machine/cpp/machine/cpu/table.h:67-110,225-239`. CPU creates the index key as `"__index"`: TS `machine/ts/machine/cpu/cpu.ts:493`; native `machine/cpp/machine/cpu/cpu.cpp:367`. At each visited Table, a nonnil direct entry wins; otherwise a Table-valued indexer supplies the next table; absent/nontable indexer ends with nil. Function-valued indexers are not invoked in these owners. **Mirrored: agrees on table-only resolution; native CPU passes that `m_indexKey` at `machine/cpp/machine/cpu/cpu.cpp:3207-3240`.**

- **The chain allows 32 visited-table lookups; exhaustion maps to `LUA_FAULT_REASON_METATABLE_LOOP` in CPU leaves.** TS limit `machine/ts/machine/cpu/table.ts:31-32`, loops `:357-369,378-390,399-411,421-438`, CPU fault `machine/ts/machine/cpu/cpu.ts:643-652,674-681,708-716`; native constants `machine/cpp/machine/cpu/table.h:16-17`, loops `:99-110,225-239`, CPU fault `machine/cpp/machine/cpu/cpu.cpp:3207-3240,3288-3296`. **Mirrored: agrees.** This is a bounded chain, not an audited general metamethod invocation system.

- **Writes in these CPU leaves program the target Table directly; they do not consult a metatable or redirect through `__newindex`.** TS general/integer/string store leaves `machine/ts/machine/cpu/cpu.ts:729-794` invoke the Table store methods. Native `machine/cpp/machine/cpu/cpu.cpp:3335-3361` invokes Table set/setInteger/setStringKeyCached; SETI/SETT fast leaves likewise directly mutate `machine/cpp/machine/cpu/cpu_dispatch.inl:94-102,152-162`. **Mirrored: agrees within inspected write boundary.** No claim about a broader metamethod library is made.
