# BLua logical-expression addendum — finite facts

Current baseline fce16b952, 2026-10-18; actual cartridge compiler and paired execution owners read directly. This corrects a missing public shared definition found by a source-blind reader. No architecture/PDF/foreign Lua specification, implementation or new execution was used.

- LG01. The source compiler routes binary And and Or to separate compileAndExpression/compileOrExpression paths. Sources: toolchain/ts/lua/compiler.ts:5351–5356.
- LG02. In a value expression, And first compiles the left expression into the target with exactly one result, emits JMPIFNOT targeting the same slot, then compiles the right expression into that same target with exactly one result; the jump skips the right expression. Thus a false-valued left supplies the selected result unchanged, otherwise the right supplies the selected single result. No Boolean-result conversion is emitted. Source: toolchain/ts/lua/compiler.ts:5528–5533.
- LG03. Or likewise compiles left into the target with exactly one result, emits JMPIF, then compiles right into the same target with exactly one result; a true-valued left skips right and remains the result, otherwise right supplies the selected single result. No Boolean-result conversion is emitted. Source: toolchain/ts/lua/compiler.ts:5535–5540.
- LG04. In a condition context, And/Or have separate left-first conditional-jump paths, which skip the unneeded right operand; unary Not reverses the requested truth test. These do not introduce eager evaluation of an unneeded right operand. Source: toolchain/ts/lua/compiler.ts:5455–5491.
- LG05. Truth is false only for Nil and False tags; all other value tags are true, including every Number value, numeric zero/NaN, empty String and object references. Sources: machine/ts/machine/cpu/value_slots.ts:157–160; machine/cpp/machine/cpu/value.h:193–197. This agrees with the existing public Branches definition; do not redefine numeric zero as false.
- LG06. JMPIF changes PC only for a true-valued register; JMPIFNOT only for false-valued, with no replacement of the tested value. Sources: machine/ts/machine/cpu/cpu.ts:2853–2863; machine/cpp/machine/cpu/cpu_dispatch.inl:429–441.
- LG07. Unary Not stores an actual Boolean that negates source truth, unlike And/Or's selected operand value. Sources: machine/ts/machine/cpu/cpu.ts:2664–2671; machine/cpp/machine/cpu/cpu_dispatch.inl:314–317.
- LG08. Source syntax precedence is Or below And, both below comparisons; Not is a unary operator. Sources: toolchain/ts/lua/syntax/parser.ts:105–131,1053–1066. The integrated source chapter already defines this; no need to duplicate the full table.
- LG09. Consequence for the real modules_manual expressions: condition and 1 or 0 supplies Number 1 for a true-valued condition and Number 0 otherwise (the intermediate 1 is true). General condition and a or b is NOT a general ternary replacement when a can be nil or false: Or selects b in that case. This is a derivation from LG02/03/05, not a new execution assertion.

Scope: ordinary linked-cartridge source expressions and the cited paired truth/jump/Not operations. No new fixed total cycle charge per source operator, eager-evaluation guarantee, Table-length/CPU7/BZ01 resolution, BIOS runtime-parser grammar or complete SDK policy. Existing CPU call-result rules remain canonical for operand call adjustment. Runtime fault/side effects in an unneeded right operand are not executed by these lowering paths; no arbitrary optimizer theorem is claimed.
