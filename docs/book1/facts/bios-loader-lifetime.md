## BIOS code storage and allocation

- **A01** `arena_capacity = 0x00040000` (262144 bytes). Storage is guest BSS `u8[arena_capacity]`, with separate BSS word `runtime_code_arena_next_block`. Payload is a raw guest address, not a guest table or native object. Header size is `isa.function_alignment`; minimum residual block is header plus function alignment. `arena_start` rounds BSS start up; `arena_end` rounds BSS end down. Initial first header is `arena_end-arena_start`; next-block word starts at arena start. Sources: `machine/bios/compiler/arena.lua:5-25`.
- **A02** Allocated flag is bit 31; size mask is `0x7fffffff`. `allocation_owners` is a guest weak-value table (`__mode='v'`) indexed by payload address. A block is reusable if allocated flag is clear **or** weak owner entry at `address+header_size` is nil. Sources: `machine/bios/compiler/arena.lua:6-11,27-30`.
- **A03** Allocation rounds `(header_size+byte_count)` up to function alignment. Fast path checks current next-block header; otherwise scans from arena start. Scan reads each raw header, coalesces consecutive reusable blocks by writing a combined free header, and returns first run large enough. It does not retain next-fit scan position when falling back to scan. Sources: `machine/bios/compiler/arena.lua:52-97`.
- **A04** Allocate consumes whole free block if residual is smaller than minimum, otherwise writes remaining header. It writes allocated header, updates next-block word (wraps only if exact arena end), stores owner under payload address, and returns payload address. Sources: `machine/bios/compiler/arena.lua:32-50`.
- **A05** Exhaustion order: current-block attempt, full scan/coalescing, synchronous `__bmsx_collect_garbage()`, second full scan/coalescing, then `error('runtime compiler memory exhausted')`. No explicit free API or rollback is present in entire 104-line module. Sources: `machine/bios/compiler/arena.lua:80-104`.

## Link layout/publication

- **L01** One arena allocation holds all function records, all upvalue descriptor words, alignment gap to instruction-byte boundary, then instruction streams. Function-record bytes = proto count * record size. Upvalue bytes = sum descriptor count * descriptor size. Code bytes = sum word count * instruction bytes. The guest const-pool table itself is not copied into this raw block; it is passed as the weak allocation owner. Sources: `machine/bios/compiler/linker.lua:7-29`.
- **L02** After allocation and before descriptor/code writes, every constant relocation replaces its guest const-pool slot with raw function-record address `function_table_address+(proto_index-1)*record_size`. Then for each proto, linker writes upvalue descriptors, function-record fields, and code words. Return is root record address and same const-pool table. No explicit transactional publication/rollback appears in link body. Sources: `machine/bios/compiler/linker.lua:31-72`.
- **L03** Descriptor word = capture index OR `upvalue_in_stack_mask` when `in_stack`. Function record fields written: code address, code byte count, parameter count, max stack, flags=0, upvalue table address, upvalue count, reserved=0. Sources: `machine/bios/compiler/linker.lua:38-67`.
- **L04** Instruction words originate as guest table entries. `write_instruction_words` byte-swaps each 32-bit packed word before raw `*u32` write and advances raw address by `isa.instruction_bytes`; native pointer indexing is not implied. Sources: `machine/bios/compiler/bytecode.lua:147-156`.

## Root/child retention

- **R01** BIOS loader fixes root const-pool register index at 1. `compile_chunk` calls compile with that index, environment, external scope, then links, then `create_root_closure(function_address,const_pool)`. Its `blua32.closure(function_address)` reads generated root descriptor; second call argument occupies r1 for capture. Sources: `machine/bios/compiler/load.lua:7,21-37`.
- **R02** Compiler program owns a guest `const_pool={}`; constants are appended and deduplicated by guest-table `constant_index_by_value[value]`. Environment and external scope are compilation program fields, not record fields. Sources: `machine/bios/compiler/compiler.lua:61-70,1881-1895`.
- **R03** For each nonroot proto compiler appends a false placeholder, records a relocation with const index and proto index, and marks that address constant needed in the parent. Root descriptor captures supplied root const-pool register as in-stack capture and assigns owner upvalue index 0. Sources: `machine/bios/compiler/compiler.lua:1904-1935`.
- **R04** Child upvalue descriptors first carry semantic captures, then required constant values captured from parent registers, then an additional in-stack descriptor of `parent.owner_register`; child `owner_upvalue_index` is that final descriptor index. Sources: `machine/bios/compiler/compiler.lua:1844-1878`.

## Frozen supplement: concrete ISA / paired consuming owners

- **I01** Generated Lua ISA constants come from TS central constants, not separately authored BIOS literals: `toolchain/ts/rompack/blua32_firmware_module.ts:37-63`. TS/C++ both define instruction bytes=4, low op bits=6, low operand bits=6, low Bx bits=12, ext A/B/C/Bx bits=2/3/3/8: `machine/ts/spec/blua32/instruction_format.ts:1-14`; `machine/cpp/spec/blua32/instruction_format.h:8-20`.
- **I02** Both raw record specs: function record 32 bytes, function alignment 16 bytes, upvalue descriptor 4 bytes, in-stack flag `0x80000000`, index mask `0x7fffffff`. Function fields byte offsets = 0/4/8/12/16/20/24/28 in L03 order. Generated Lua word indices are byte offsets shifted right 2 (0..7). Sources: `machine/ts/spec/blua32/image_format.ts:30-46`; `machine/cpp/spec/blua32/image_format.h:36-52`; `toolchain/ts/rompack/blua32_firmware_module.ts:52-63`.
- **I03** Consequently A01 header=16 bytes, minimum split residual=32 bytes. Usable gross span is the aligned interior of declared 256 KiB BSS, not necessarily all 262144 bytes for payload. One allocation also pays its 16-byte header and final rounding. Sources: `machine/bios/compiler/arena.lua:5-9,16-25,32-50,80-83`; constant values I02.
- **I04** Function record consumers latch code address, parameter count, max stack, flags, upvalue table address/count from mapped little-endian words; code byte count and reserved field are not read by these reader bodies. They have direct mapped-page path or six mapped-bus word reads, returning false on changed bus-fault sequence in bus path. Sources: `machine/ts/machine/cpu/cpu.ts:1424-1496`; `machine/cpp/machine/cpu/cpu.cpp:1019-1079`.
- **I05** `readFunctionRecordOnBus` uses execution-domain lookup for record address; null/unowned address-domain lookup uses ambient image. Missing selected image makes read fail. This is address/image selection, not a newly installed runtime program image. Sources: `machine/ts/machine/cpu/cpu.ts:1499-1508`; `machine/cpp/machine/cpu/cpu.cpp:1082-1092`.

## Frozen supplement: actual capture, calls, and collection

- **C01** Nested function expression emits CLOSURE using a register containing relocated function address; bytecode encoder emits WIDE prefix carrying closure-address-register marker then CLOSURE. Sources: `machine/bios/compiler/compiler.lua:851-856`; `machine/bios/compiler/bytecode.lua:121-145`. In both dispatchers marker selects numeric register address rather than immediate `bx*16`; read failure hard-halts; successful create publishes Closure in target register. Sources: `machine/ts/machine/cpu/cpu.ts:2865-2884`; `machine/cpp/machine/cpu/cpu_dispatch.inl:443-460`.
- **C02** For generated records flags=0 (L03), closure creation does not take static/no-upvalue canonicalization branch. Creation first reads all descriptor words, resolves existing open captures by frame/index or parent's upvalue reference, counts missing open captures, reserves tracked closure/upvalue bytes, then allocates closure and missing Upvalues and links them into frame. Descriptor-bus failure hard-halts before published target Closure; TS allocates upvalue array before descriptor scan, C++ uses resized scratch arrays. Sources: `machine/ts/machine/cpu/cpu.ts:3302-3359`; `machine/cpp/machine/cpu/cpu.cpp:2907-2964`.
- **C03** Closing captures copies actual frame register values into Upvalues, sets open=false, clears frame and linked-list references. Ordinary RET invokes close before unwinding. Therefore R01 root's const-pool reference survives its create-root helper returning by closed Upvalue storage; it is not a borrowed pointer to helper's stack register. Sources: `machine/ts/machine/cpu/cpu.ts:2942-2954,3362-3374`; `machine/cpp/machine/cpu/cpu_dispatch.inl:506-508`; `machine/cpp/machine/cpu/cpu.cpp:2967-2977`; root R01/R03.
- **C04** Compiler reserves owner register for root or any function with semantic children; root startup GETUP loads pool owner there and GETI reads required pool slots. Nonroot startup GETUP loads required constants and owner register (where present). Child descriptors always include parent owner capture (R04). Thus even an escaping child retains the allocation-owner const-pool table by an extra capture; not just its individually needed scalar/constants. Sources: `machine/bios/compiler/compiler.lua:1674-1677,1699-1735,1873-1878`.
- **C05** Runtime call hot-path re-reads raw function record from closure's address, binds frame to selected image, sets PC from latched code address, and sizes/registers from max stack/params. No runtime compiler-proto object is the callee representation. Sources: `machine/ts/machine/cpu/cpu.ts:3187-3236`; `machine/cpp/machine/cpu/cpu.cpp:2995-3030`.
- **G01** Both collectors trace live Closure -> Upvalues; closed capture -> stored guest value, open capture -> owning thread/frame storage. Both recognize weak table modes and clear dead weak values. BIOS allocator weak ownership therefore does not itself retain an otherwise unreachable pool. This is the sourced retention mechanism, not proof of every collector behavior. Sources: `machine/ts/machine/cpu/cpu.ts:338-352,4938-4958,5025-5043,5056-5089,5101-5110`; `machine/cpp/machine/cpu/cpu.cpp:139-202,223-231`; allocator `machine/bios/compiler/arena.lua:11,27-30`.
- **G02** Arena explicit collection dispatch reaches TS `collectTrackedHeapBytes()` / C++ `collectHeap()`. Sources: `machine/ts/machine/cpu/cpu.ts:3719-3721`; `machine/cpp/machine/cpu/cpu.cpp:1762-1764`; arena call `machine/bios/compiler/arena.lua:96-99`.
- **G03** Separate guest object-heap accounting capacity = configured ramByteCount minus `BASE_RAM_USED_SIZE`; central memory constants set that subtraction to geometry scratch size `0x80000`. Minimum collection threshold 1 MiB; allocation may collect, recompute, and then throw heap OOM. This tracked guest-object heap is not the BIOS 256 KiB raw executable block pool and does not provide arena payload addresses. Sources: `machine/ts/machine/cpu/lua_heap.ts:9-58`; `machine/cpp/machine/cpu/lua_heap.h:16-43`; `machine/cpp/machine/cpu/lua_heap.cpp:11-33`; `machine/ts/spec/bmsx/memory_map.ts:25-30`; `machine/cpp/spec/bmsx/memory_map.h:31-36`.

## Frozen supplement: address placement and limited retention evidence

- **P01** System link data begins at `DYNAMIC_RAM_BASE = RAM_BASE + IO_REGION_SIZE + GEO_SCRATCH_SIZE = 0x080c0000`; BSS begins after system data bytes. BIOS runtime arena is within that system BSS by declaration, but its final symbol offset/absolute address is deliberately unverified. Cartridge static data begins after linked BIOS BSS (`cartridgeStaticRamBase`), cart BSS after cart data. Linker rejects static layout beyond configured RAM. This establishes disjoint declared static layouts, not a separate host executable arena. Sources: `machine/ts/spec/bmsx/memory_map.ts:6,25-30`; `machine/cpp/spec/bmsx/memory_map.h:31-36`; `toolchain/ts/rompack/blua32_linker.ts:285-289,1072-1073,1107-1120,1136-1149`; arena declaration `machine/bios/compiler/arena.lua:13-25`.
- **S01** TS/C++ Memory save-state captures copy RAM, and restore copies RAM back and invalidates mapped RAM range. Consequently raw code-arena bytes/header/next-block storage are RAM-save-state data rather than retained host allocations. Sources: `machine/ts/machine/memory/memory.ts:289-310`; `machine/cpp/machine/memory/memory.cpp:204-225`; A01.
- **S02** TS/C++ CPU snapshot serialization has ordinary Table object records, Closure function-address/canonical/upvalue-count+references, and Upvalue open/index/thread/frame-index+value. Restore reconstructs Table/Closure/Upvalue objects and relinks references; no function byte stream is serialized inside Closure records. Sources: `machine/ts/machine/cpu/cpu.ts:4560-4590,4670-4705,4713-4730`; `machine/cpp/machine/cpu/cpu.cpp:1331-1361,1431-1467,1477-1491`. This is evidence of generic retention machinery only; no entire save-state roundtrip or all-state parity was tested here.
- **S03** CPU reset closes active callstack captures, clears completion values/static-closure cache/image residency, activates system boot image, pushes system startup closure, and collects heap. `clearExecutionEnvironment` clears completion, stack, globals. Neither of those CPU method bodies explicitly resets BIOS arena BSS headers; BIOS allocator initialization writes first header/next pointer when module initialization runs. Full reset/boot/module initialization ordering and guest-global survival are deliberately unverified. Sources: `machine/ts/machine/cpu/cpu.ts:841-909,923-927`; `machine/cpp/machine/cpu/cpu.cpp:431-473,716-720,3388-3416`; `machine/bios/compiler/arena.lua:23-25`.

## Frozen supplement: environment/external-scope lifetime boundary

- **E01** If identifier uses environment key, compiler adds actual environment guest value and key to constant pool. External binding adds actual location guest value plus chosen external read/write closure. Compiler's original `program`/names containers are not copied into function record. Sources: `machine/bios/compiler/compiler.lua:76-96,1890-1895`; link record L03. Whether an unused supplied environment remains reachable is not promised; only constants actually added are captured.
- **E02** Actual frame scope producer `frame.open` returns names/read/write/close. Read/write capture lifetime scope and frame index, not a copied binding value. Both first read `scope.thread`; nil raises exactly `Selected frame evaluation has ended.` Read of address location returns location.index; otherwise accesses live selected-frame upvalue/register; write accesses corresponding live location. Close sets scope.thread=nil and unregisters scope. Sources: `machine/bios/debug/frame.lua:37-70`; `machine/bios/debug/frame_scopes.lua:14-17`.
- **E03** Registry is ordinary guest weak-key table. `open` stores scope `{thread,owner_frame}` as key with true value; `retire(thread,first_frame)` closes matching scope records whose owner_frame>=first_frame. Sources: `machine/bios/debug/frame_scopes.lua:1-25`.
- **E04** Actual firmware evaluator opens scope with current thread's last frame as owner, passes it to compilation, and its protected-result forwarding helper calls `scope.close()` before returning the protected tuple. Thus compiled escaping accessors survive as closures but lose borrowed activation access after evaluator completion; check remains in accessor when called later. Sources: `machine/bios/shell/repl.lua:33-55`; `machine/bios/debug/frame.lua:42-69`.
- **E05** Other sourced retire calls: firmware coroutine.close wraps primitive close then retires all thread scopes (`first_frame=0`); IDE source install retires before media installation; failed-completion Hot Resume retires from failed-completion frame before CPU abort. IDE retirement manipulates same guest registry and nulls thread reference. These are exact callsites, not full UI lifecycle proof. Sources: `machine/bios/coroutine.lua:21-26`; `ide/runtime/hot_resume.ts:243-248,439-442`; `ide/runtime/frame_scopes.ts:8-23`.
