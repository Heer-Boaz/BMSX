# Protected calls and coroutines: paragraph assignments

Scope: installed language execution contexts, not a new device, operating-system
scheduler, or replacement for CPU/Memory/IRQ/SYSTEM reference. CPU values and
byte storage remain distinct. No architecture document or reference PDF input.

1. Installed BIOS availability and actual public signatures: surface extractor
   supplies a narrow installation subset; inventory of remaining BIOS APIs is
   editorial backlog, not a promise that this chapter finishes the environment.
2. error/pcall/xpcall: separate paired-owner extractor, then facts-only author.
   Cover value/count movement, arbitrary/nil errors, handler limits, caught
   language faults versus hardware exception boundaries and additional charges.
3. coroutine create/resume/yield/status/running/close/isyieldable/wrap: separate
   paired-owner extractor and author. Explain visible states, exact argument and
   result movement, closure lifetime, failed versus closed, and hardware context
   limits. Do not import stock-Lua behavior or represent threads as raw words.
4. Root complete ordinary cartridge: typed results plus every entry line,
   executable BIOS calls, ordered observations and actual output. No hidden
   helper, direct private primitive, fake register array or host-only callback.
5. Language-transfer diagram from frozen facts; no physical timing scale or
   invented concurrent processors. Audit every arrow and label independently.
6. Nonauthors check literal claims against live paired lines; public-only reader
   reconstructs the whole program; actual generated PDF pages reviewed at full
   readable size. Existing publishing path only; no framework or validator work.

Owner disagreements stop only affected common claims and remain explicitly
tracked. A successful program or bounded semantic pass is not evidence that
whole-console newcomer acceptance, all BIOS libraries or the cartridge/expansion reference is finished.
